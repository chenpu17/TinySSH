## 3. R03：必须在冻结前修正的契约

### C-01 取消/Ready 矛盾及身份边界（P1）

`docs/ux/ux-r1-g0/r03-contracts.md:37` 说 Ready 后不变，`:40` 又改 Cancelled；`:40/:52` 自动关闭即显示已取消，未定义关闭失败/处理中、Ready 交付后的取消期限、终态对账保留。`:43–44` 将 Agent 建连也纳入纯 host 合并，与 C2 按 Actor 设 owner 冲突。

修复：明确交付与取消的线性化点、关闭成功/失败返回、终态查询/保留策略；同主机合并只适用于同一授权身份/明确的人类 UI 调用域，跨 Human/Agent 或不同 client 不合并、不共享审批或取消权限。用竞态和关闭失败序列冻结预期。

### C-02 文件提交策略及 fixture 相矛盾（P1）

`r03-contracts.md:170/:186` 仍是无 posix-rename 时双 rename 并回滚；`r03-fixtures.md:22` 要求同情况阻止替换。第一步移走目标后断线可能让原路径缺失；应答丢失后回滚还违反 OutcomeUnknown 不自动回滚规则。

此外 `r03-contracts.md:168/:182` 未把 collision 与最终发布原语绑定。目标预检不存在，发布前被其他进程创建，统一 posix-rename 可覆盖它；默认 fail 因而失效。`:179` 的通用 AwaitingDecision 与 Agent 永不进入此状态也冲突。

修复：按本报告产品裁决重写唯一发布决策表，分别定义 overwrite 和 no-clobber 分支，明确 Agent 复检冲突的错误返回，同步 fixture。仅在会议上同意“阻止替换”而保留双 rename 正文不能算关闭。

### C-03 C10 输出恢复不足以重建终端（P1，G1 直接前置）

`r03-contracts.md:275–277` 规定 alt-screen 活跃时退回 ScreenSnapshot，现有 `crates/session-api/src/lib.rs:531–538` 只有文本、光标、尺寸、alt_screen 布尔值；不能重建 vim/top 的单元格属性、主副缓冲区及终端模式。`:285` 仅说快照和 seq 同锁，未定义 receiver 注册、返回前 live 帧暂存、去重和 resync 衔接；`:286` 等 send 失败清理也没有覆盖静默会话的显式卸载。

修复：冻结可重建渲染状态的快照或检查点重放方案、接入与恢复的水位顺序、明确订阅取消。补 alt-screen、快照返回前 live 帧、静默会话关闭用例。这里要求冻结方案，不要求现在实现 R11。

### C-04 关键操作 wire 缺失（P2，阻塞 R03 签署）

`r03-contracts.md:132–143` 未定义提交人类 CollisionDecision 及拒绝过期决定的命令；`:252–253` 只有 collaboration_status，没有启停及选择等待/停止策略的请求/响应，且“原因可查”的 DTO 无原因字段。`:182` 将 Tauri 的 upload_file/download_file 误写为 MCP 工具名，实际为 upload/download（`crates/mcp-server/src/lib.rs:429/:444`）。

### Q-01 成功判定会接纳失败日志（P1）

`p3_connect.py:70–75` 和 `p6_cycles.py:73–79` 只匹配 autoconnect；`src-tauri/src/main.rs:852–853` 成功/失败都含该词。raw 未保存匹配原文/sid/状态。失败字符串纯探针已证明可误判；这不表示实际30次必然失败，而是现有证据无法证明成功。

必须精确接受目标host、有效sid和期望状态的成功事件，失败单列并保存原文/run ID。旧版 core 完成与新版普通 SSH 不等待 shell marker 的目标需区分。

**补查修正**：主审随后只读检查了仍存在的 `/tmp/r4_p3/run_1.err` 至 `run_30.err`，30份均含成功形态日志，未发现失败形态日志。见[临时日志恢复记录](ephemeral-log-recovery.json)。这些记录支持本次实际建连成功，不能因matcher漏洞断言30次失败。团队应优先核对其与raw各run/PID/时序的对应并补充归档，能证明同一运行的部分无需无谓重跑；无法绑定的样本再补测。这个补查不修复通用脚本会误接纳失败日志的问题，也不证明UI可交互端点。

### Q-02 P6 测错生命周期（P1）

`p6_cycles.py:66–87` 每轮新起应用再 TERM，进程退出清掉了应当被检测的进程内资源积累。报告“旧版无标签”亦不准确：`ui/src/App.tsx:1230–1245/:1902–1917` 已有会话切换和 tabbar。

撤销 P6 达标，保留进程残留证据；补同一 release 进程内100次会话创建/关闭，测200次切换及适用的视图变化。不能观察订阅数量的旧版部分如实标未完成，不用整进程退出代替。

### Q-03 现有输入护栏未封闭错误实例与投递竞态（P1）

`keyguard.py:20–40` 只认进程名及任意同名1280×800窗口，没有本次proc.pid、窗口PID/实例或控件。`ev.py:17–18` 随后向全局 HID 投递；verify到子进程实际投递存在焦点变化窗口。日常实例同名前台即可通过现有guard，按下/松开之间也能切焦点。

**当前决定：不批准在用户日常桌面继续运行这些全局注入脚本，不把15分钟空闲视作安全修复。** 先改成独立测试登录会话/专用机，或经过验证的本次PID/窗口定向驱动；在实际投递函数内检查目标，明确异常中止和finally清理，并测试错误实例、焦点变化、目标控件消失的拒绝路径。不得退出用户浏览器来迁就测量。

### Q-04 P1 端点不成立（P2）

`main.rs:655–669` 只等添加按钮/表单；该按钮 `App.tsx:1664` 无条件渲染，列表通过独立异步链加载（`:505–509`）。s2减700不能推导“20台主机列表已可操作”。固定等待是服务端延迟请求，失败被`:633`吞掉；共享信标仍无run ID。

### Q-05 内存归属不是 fail-closed（P2）

`memsample.py:55–58/:71/:84–91` 与 `p5_pilot.py:65–70` 启动时冻结PID，采样中消失记0，新helper漏计；退出时旧PID消失仍可PASS。最终JSON缺全过程逐进程曲线/启动身份；启动新增加退出消失仍只是候选相关性。
