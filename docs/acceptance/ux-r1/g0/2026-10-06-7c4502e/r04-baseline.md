## 2. 统计方法（全部采样统一）

- **可操作口径（P1，独立审核后修正）**：`operable = s2 信标时间戳 − 700ms 固定偏移`。s2 语义为 SMOKE 注入脚本「添加主机表单进入 key 模式」：点按钮 → sleep(400) → waitFor(select) → sleep(300) → 打标（src-tauri/src/main.rs SMOKE 流程），故固定偏移为 700ms；s2 隐含列表视图已渲染可点击（openBtn 已找到并点击），对「主机列表可操作」是保守（偏晚）代理。初版 400ms 口径漏计第二个 sleep(300)，已审后从原始 `s2_ms` 全量重算（原始 runs 内保留 `operable_ms_v1_400offset` 字段）。主机列表为本地 SQLite 渲染，启动路径无网络等待（P1 环境未设 AUTOCONNECT）。
- **P95**：`statistics.quantiles(n=20, method="inclusive")[18]`。exclusive 法在 n=10 时外推出数据范围（实测 2124 > max 1714），故统一 inclusive。
- **样本数**：P1 冷/热各 10（交付要求各 10）；P3 30；P6 100。
- **异常值处理**：不剔除。冷启动 #5（1714ms）保留在分布内；污染样本的处理见 §5.2（重跑替换并保留 `replaced` 注记，非删除）。
- **仪表下限**：P1/P3 的 stderr 轮询 5ms；P6 的 ps 采样周期；P2（若复测）screencapture 周期 40-90ms 记为上限。所有口径在原始 JSON `protocol` 字段随数据归档。

## 3. 实测明细

### 3.1 P1 启动（raw/cold.json、raw/warm.json；cold_retry.json 为 §5.2 重跑的独立产物）

- 冷（进程级冷启动，前次退出后 idle 60s）：n=10，min 429 / 中位 460 / P95 1004 / max 1414 ms。
- 热（进程级热，连续启动）：n=10，min 464 / 中位 488 / P95 505 / max 509 ms——热启动分布显著更紧（极差 45ms vs 冷 985ms），符合预期。
- 分解参考（信标阶段，非门指标）：s1（进程起来）≈307-490ms，s2（打标时刻，含 700ms 固定偏移）≈1129-2114ms。

### 3.2 P3 建连（raw/p3.json）

- 口径：spawn → stderr `[app] autoconnect` 行（就绪信号实测发现：AUTOCONNECT 模式建连完成后打点）。
- 30/30 成功，min 312 / 中位 330 / P95 349 / max 351 ms。
- 限制登记：未改版基线无法分解应用内阶段（DNS/TCP/认证/终端就绪），`不等待 shell marker` 的分解验证归新实现（C10 序列）。

### 3.3 P6 资源循环（raw/p6_cycles.json；独立审核后带退出核验重跑版）

- 100 次 spawn→AUTOCONNECT→就绪→TERM 循环；每循环差分归属 RSS（应用 + 启动新增 WebKit 辅助进程），**每次退出后核验该循环候选全部消失**（差分法第④步）——100/100 循环零残留。
- 首 10 循环中位 254.00 MB → 末 10 循环中位 252.94 MB，**Δ = −1.06 MB**（2 位小数精确值，审计修正：初报"Δ=0.0"系 1 位小数舍入假象）；全程 min 246.92 / max 279.94 MB。无随循环次数的线性资源增长。
- 单循环 spawn→就绪中位 310ms（兼作 P1 建连路径大样本旁证）。
- 说明：绝对 RSS 水位随系统状态在多次运行间浮动（本次 ~254 vs 前次 ~227），门断言只看单次运行内的跨循环趋势。

## 4. P5 内存试点（raw/p5_pilot.json，缩时协议登记）

**试点结果（2026-10-06，raw/p5_pilot.json）**：输出源为容器 `/root/.bashrc` 挂 `/root/.spew` 开关（存在即循环输出 ~80 字节 base64 行），AUTOCONNECT 会话自动喷发，全程零键注入。差分归属 3 候选辅助进程（WebContent/GPU/Networking），**退出后零残留**。

- 预热（喷发 60s 填满 scrollback/lossless 缓存）→ 静置 60s → B = **328.0 MB**（60s×12 样本中位）。
- 持续输出 300s：曲线 328.2 → 331.7 MB，输出期间增量递减趋缓。
- 停止 → 静置 60s → E = **332.0 MB**（60s×12 样本中位）；**增长 (E−B)/B = 1.2%**（门限 ≤20%）。
- **如实披露（审核发现）**：E 段 12 个样本并非平稳——末 4 个样本阶跃至 ~334.4MB（输出已停止后仍 +2.4MB，可能为 GC/缓冲延迟回收或页缓存回迁）。按口径 E 取 60s 中位数即 332.0；若按末段稳定值计，增长为 2.0%，仍远低于 20% 门限。该停止后缓升现象登记给 R51 全量协议观察（其末 10 分钟逐分钟中位数规则会显式捕捉）。
- 退出后零残留（差分法第④步核验通过）。

**协议差异与偏差登记**：①缩时——持续输出 5 分钟（全量 30 分钟）、单会话（全量 10 会话）；②名义 1k 行/s 未标定（实测速率随容器调度浮动，~80 字节 base64 行/次）；③交付 §4 要求「采样前冻结 rows/cols/行内容/缓存上限」——试点实际条件：窗口默认 1280x800、xterm scrollback=5000（ui/src/App.tsx:671 旧版默认）、行内容为随机 base64（约 108 字节/行含换行），为事后登记而非事前冻结；R51 全量协议执行前须按 §4 正式冻结。B/E 口径与交付 §4 一致：预热填满缓存 → 静置 60s 采 60s 中位数 B → 测试 → 静置 60s 采 60s 中位数 E → `(E-B)/B`。

## 5. 事故与污染记录（原始数据完整保留注记）

### 5.1 P2 键注入事故（2026-10-06，用户影响级）

p2_switch 前置步骤 `osascript set frontmost` 因目标进程非前台而静默失败（capture_output 吞错），CGEvent Cmd+1/2 可能落入当时前台的用户应用约 6 分钟。处置：立即终止采样进程与应用实例；该时段产出数据全部作废不归档；**所有键注入采样（P2 切换/回显、P4 下载、P7）延期**，复测条件见 §5.4。已向用户披露。

### 5.2 P1 冷启动污染

P3 bootstrap 应用成为孤儿进程后其 SMOKE 信标写入共享信标日志，混入 P1 冷启动 #3/#4 计时（污染原值 2140/1856ms，-400 口径；已回填至 cold.json 对应 run 的 `polluted_original_operable_ms_v1` 字段）。处置：终止孤儿；bootstrap 增加 超时必 kill；#3/#4 重跑（-700 口径 461/477ms）替换，cold.json 保留 `replaced` 注记；重跑的独立统计产物为 raw/cold_retry.json（n=2，中位 469 / P95 476ms，与 cold.json idx 3/4 同源）。

### 5.3 归属方法修正

零基线方案（要求退出全部 WebKit 宿主）与用户"浏览器不能退出"约束冲突 → 改差分归属（启动新增 + 退出消失双向核验），实证记录见 r04-environment.md §2.1。

### 5.4 P2/P4/P7 复测条件（已冻结，待用户空闲窗口）

1. **约 15 分钟机器空闲窗口**（无键注入落点风险）。
2. 脚本硬护栏（审核后已实现于 scripts/perf/keyguard.py，p2_switch/p2_echo/p4_download 每次键/点击事件前调用）：① 前台进程 = tinyssh-app（osascript 返回值精确匹配，失败即中止）② 主窗口 1280x800 在屏；任一不满足立即 abort，不发送任何事件。护栏延迟不计入计时窗口。
3. p4_download 需先截图标定「按路径下载」输入框坐标（--ix/--iy）。
4. 复测数据以 `retest-<date>` 前缀归档至本目录。
