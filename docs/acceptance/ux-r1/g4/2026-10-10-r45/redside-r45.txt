# R45 红侧：新回归入口的判别力证明

目的：证明 `ui/test/` 这套入口**真的在测被测物**，而不是「自己跟自己对」的空断言。
方法：对**被测源码**做定点变异（不是对断言做变异），跑对应 spec，看是否**恰好**在该点变红。
还原一律用 Edit 反向改回（**不用** `cp` 整文件写回，避免吞掉并行修复）。
每轮结束后 `git diff --stat -- ui/src/` 复核被测文件已回到 HEAD。

> 本文件在独立审核 rev-r45 / vis-r45 之后**扩写**：审核者发现的三处缺口
> （06 主体筛选、02/11 终端可见性、15 H1 瞬态）已修，并把他们的变异与作者的变异一并留证。
> 审核**之前**的原始记录保留在文末「附录：审核前记录」。

### A2：为什么「未检出」不是缺陷

`gripMove` 只决定拖动**过程中**的中间宽度；spec 读的是**松手落定后**的宽度，
落定宽度由 `gripUp`（A3）的限幅决定。即该断言锚定的是**用户可见的最终契约**
（松手后停在 200–300），不是拖动中间帧。若日后要覆盖中间帧，需另加
「拖到 x=50 且**不松手**时实测宽度」的采样断言；本轮未做，**不主张**。

### A4：审核者发现的真缺口（已闭合）

rev-r45 的 M3 把主体筛选改成完全空操作，旧断言只写 `nAgent <= nAll`，
**14/14 全过**——筛选坏了也发现不了。处置：断言改为**逐行核对 `data-actor`**，
并要求 `nAgent < nAll`。同一变异现在：

```
 FAIL  筛 Agent 后行数减少（筛选真的生效）  — Agent 5 vs 全部 5
 FAIL  筛 Agent 后每行主体都是 agent  — human,human,agent,agent,human
```

事件类型筛选同样补强（逐行核对 `data-action === "exec"` 且行数减少）。

### A5 / A6：H1 是**双重防线**，如实分级

H1（v1.37）的缺陷是：切会话时输入框**短暂显示上一会话的委托**，随手一存就把 A 的任务写进 B。
复现该缺陷需**完整摘除**两处防线（`:958` 简报回填 + `:967` 即时清空）——此时
**101/101 帧**泄漏，断言红。**只摘一处则不红**：另一处兜住。

这不是断言缺陷，是**冗余防线**的固有性质（与 R34「复检为冗余防线，摘除不被判别，保留」同型）。
如实登记：**本断言证明的是「该缺陷类整体不存在」，不证明「每一处防线各自必要」。**

顺带记录一个**断言自身的坑**（已修）：H1 的瞬态断言最初用「已保存的目标 + 新连接」路径，
结果**空转**——新连接会关掉面板，输入框根本不在 DOM 里，采样为空自然不泄漏。
改为**未保存草稿 + 标签页切换**（面板保持打开，101 帧输入框全在场）后才真正咬住，
并加了一条 `输入框一直在（断言不是空转）` 兜底，防止再次退化为空转。

## 三、失败可识别性（见 `exit-codes.txt`）

| 场景 | 退出码 |
|---|---|
| 全部通过 | 0 |
| 注入必失败断言 | 1 |
| dev server 未起（端口 5999） | 2 |
| `TINYSSH_UI_CHROME` 指向不存在文件 | 2 |

三类**互不混淆**：断言失败（1）与环境问题（2）可区分，不会把「没起服务」误读成「功能坏了」。
