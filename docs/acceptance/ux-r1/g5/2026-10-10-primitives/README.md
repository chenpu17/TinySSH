# 阶段 B 原生原语验证（`winsize.py` / `ev2.py`）

> 计划：「原生窗口 resize 原语、`ev.py` drag 原语均为**新增能力**，本身需验证后再用于
> 取证」。本目录为 `winsize.py` 的 `set` 路径实测原始件。

## 1. 验证对象与条件

- 被测原语：`scripts/native-smoke/winsize.py`（AX C API 经 ctypes 直调）。
- 被测应用：**tinyssh-app**（`target/release/tinyssh-app`，主树开发产物，
  sha256 `3bfecdf0d793449126fdf8187a6940c4d8caa0009971e941d14f92dfe3905773`）。
  **未对任何用户应用做写入**（用户长期指令：不打扰用户环境）。
- 环境：屏幕**已解锁**；前台为 Termius（用户应用），全程未动它。
- 显示器：主显示器 origin=(0,0) size=**1512×982**（另有一台 1920×1200 在 origin=(-1920,42)，
  本轮未涉及）。
- **两份原始件各自记录**被测二进制路径与 SHA256、锁屏读数、显示器边界、app pid：
  `winsize-set-verify.log`（2026-10-10 10:39:48，app pid=94413）与
  `winsize-pos-verify.log`（10:40:34，app pid=95044）。两份是**同一坐次、同一二进制**
  的两次启动（各次独立拉起被测应用，故 pid 不同；二进制 SHA256 两份相同且等于上方值）。
  - 锁屏读数记两条：`CGSSessionScreenIsLocked` 原始值 = `None`（解锁时该键**缺失**）
    与 `winsize.screen_locked()` = `False`（脚本判定），二者一致。

## 2. 实测结果

### 2.1 尺寸与位置投递

| 项 | 请求 | 读回 | 退出码 |
|---|---|---|---|
| 尺寸（实变） | 1280×800 @ (100,71) | **1280×800** | 0 |
| 尺寸（实变） | 960×640 @ (100,71) | **960×640** | 0 |
| 尺寸（低于最小值→夹取） | 400×300 @ (100,71) | **960×600** | **5** |
| 尺寸+位置 | 1000×700 @ (300,200) | 1000×700 @ (300,200) | 0 |

- **`set` 真实投递成立**：读回等于请求，且含**真实变化**（1000×700→1280×800→960×640），
  非「设了没生效」。
- **fail-closed 夹取判定成立**：400×300 被窗口管理器夹到 960×600（`tauri.conf.json`
  的 `minWidth=960/minHeight=600`），脚本读回比对后 **exit 5** 并明示「该尺寸不得作为证据」。
- **位置投递成立**：`--x/--y` 生效并读回一致。

### 2.2 位置相关夹取机制（实测，**E01 必读**）

窗口管理器按窗口**当前**位置夹取请求尺寸——**尺寸先于位置生效**。控制实验
（`winsize-set-verify.log` D 段，唯一变量是窗口的**先前位置**）：

| 步 | 窗口先前位置 | 请求 | 读回 | 退出码 |
|---|---|---|---|---|
| D2 | (300,200) | 1280×800（不给位置） | **1212×782** | 5 |
| D4 | (100,71) | 1280×800（不给位置） | **1280×800** | 0 |
| D5 | (100,71) | 1280×800 **且** @ (300,200) | 1280×800 @ (300,200) | 0 |

D2 的夹取值恰为 `1512−300 = 1212`、`982−200 = 782`（即主显示器右/下边缘减去**旧位置**）；
D4 同请求在留得下空间的位置上被原样采纳。D5 说明：带 `--x/--y` 时**尺寸按旧位置夹取**、
随后才移动位置，故窗口可停在**部分离屏**处。

⇒ **要把窗口设成某尺寸，须先把它放到留得下该尺寸的位置**；否则 `set` 会 fail-closed
exit 5。调用方须知道这可能是**位置**问题而非尺寸不可设。

原始件：`winsize-set-verify.log`、`winsize-pos-verify.log`（各自含被测二进制路径与
SHA256、锁屏读数、显示器边界、每步命令与读回）。

## 3. 由此得到的 E01 约束（重要）

1. `src-tauri/tauri.conf.json` 同时设置 `minWidth: 960`、`minHeight: 600`（**新旧两棵树
   相同**）。实测确认原生窗口**不可能小于 960×600**（400×300 被夹取）。
   ⇒ **E01 的窄尺寸（320/360/640 等 < 960 宽）在原生窗口上不可达**，只能由浏览器
   viewport sweep 覆盖（计划中 E01 的浏览器行已含 `harness.cjs` viewport 与 R31 断点）。
   原生截图轮只应覆盖 **≥960×600** 的尺寸。此约束须写入 E01 执行口径，**不得**在原生轮
   声称覆盖了窄尺寸。
2. 逐尺寸取证前须**先把窗口移到留得下该尺寸的位置**（见 §2.2），否则会被静默夹取而
   只以 exit 5 暴露；脚本不会把夹取当成功，但**证据轮不得忽略 exit 5**。

## 4. 口径与未做（未覆盖项逐条登记，不主张）

- **未验证**：`ev2.py` 的 `drag` 真实投递（需 E07 场景中的接收端；本目录不含）；
  **多显示器**下的 `set` 行为（本轮全在主显示器；副显示器 origin=(-1920,42) 未测，
  §2.2 的夹取边界是否按「窗口所在显示器」计算**未验证**）；`set` 在窗口被最小化/
  全屏态时的行为。
- §2.2 的机制结论建立在**单次会话、单台显示器**的控制实验上（D2/D4 各 1 次）。
  方向明确（两个预测均命中），但**重复次数少**，不主张统计稳健性。
- 被测二进制是**主树开发产物**（加载 `http://localhost:5183` dev 前端，非内嵌资产）——
  本目录只证明**原语**行为，**不**作为应用打包行为的证据。
- **读回比对有 ±1px 盲带**：`set` 的读回比对用 `SIZE_TOLERANCE = 1.0`，每维差 ≤1px 判为
  采纳（exit 0）。故 §2 的「读回=请求」按 ±1px 成立；**1px 以内的夹取不会以 exit 5 暴露**
  （独立复核实测：请求 1213×783 被夹到 1212×782 → exit 0）。逐像素精确须自查读回值。
