## 4. 发现（登记，本档不修）

**E03-1（中）长中文主机名在**主机卡自身**上截断后，卡内无视觉读全称的路径**

- 现象：名称 `scrollWidth 575` vs `clientWidth 151`，被省略号截断到约 10 字
  （截图 `longhost-default.png` 显示为「生产环境核心交易数据…」）。
- 三条可能的视觉读全称路径**全部缺失**（`e03-raw.json.longHost`）：
  1. `.host-name` 无 `title`（`App.tsx:3423` 无该属性）；
  2. `.host-card-main` 的 `title` 在**无会话时**为 `undefined`（`App.tsx:3410-3412`），
     有会话时也只含 `username@address:port`/指纹/编码，**仍无名称**；
  3. `.host-card` 的 `title`（`App.tsx:3407`）同样是 `username@address:port` + 指纹 + 编码，
     **不含名称**。
- 唯一带全名的是 `aria-label`（`App.tsx:3400`）——**仅屏幕阅读器可及**，对视力用户不可见。
- 影响：当一台主机名较长且**前缀相同**（如多台「生产环境核心交易数据库主节点…-只读副本-NN」），
  视力用户在**不打开编辑对话框、且连接未失败**的前提下**无法靠名称区分**它们（地址行可区分，
  但名称本身不可读）——这是「目标身份被挤掉」的一种。
- **限定（2026-10-10 独立复核后更正）**：本档初版写「无法在 UI 上区分」，**超出证据**。
  实测另有**一条**真正视觉可读的**有条件**路径：① 连接**失败**时横幅完整显示全名（§3.2，`longerror.png`）。
  （曾被列为 ② 的路径——点「编辑主机」后表单 `name` 预填 `editHost?.name`，`App.tsx:5404`——
  **不构成视觉读全称路径**：该表单与「添加主机」共用同一个**窄侧栏卡片布局**（`App.tsx:5526` 单一
  `.card.add-host`），名称输入框内宽仅约 30px，45 字中文名只渲染约 2 字（见本包 `ipv6-reject.png`：
  「ipv6-探针主机」只显示「ipv」）⇒ 顶多「点进字段后靠光标滚动逐字读」。此点由独立视觉复核以像素
  证伪，2026-10-10。）故准确表述是「**主机卡自身（含悬停）**无视觉读全称路径」——标题已按此收窄。
- 建议（**不在本档实施**）：给 `.host-name` 加 `title={h.name}`，或把名称补进
  `.host-card` 的 `title`。二者都是单行改动，且**不引入新溢出**（`title` 是浏览器原生提示）。
- 本档口径：这是**视觉域**发现；截图已出，最终「是否可接受」由人眼定。

**E03-2（低）IPv6 字面量被地址校验拒绝**

- 校验 `App.tsx:5475` 的字符集 `[a-zA-Z0-9._-]` 不含冒号 ⇒ 无法录入 IPv6 字面量
  （`ipv6-reject.png`）。**主机地址录入**路径只有这一条正则，无其他入口。
- **限定（2026-10-10 独立复核后更正）**：本档初版称「唯一 IPv6 相关代码是
  `crates/transport-ssh/src/lib.rs:1247`」，**不成立**——`ui/src/App.tsx:2764` 的
  `isLoopbackAddr` 显式识别 `"::1"`/`"0:0:0:0:0:0:0:1"`（端口转发的监听地址，用户可键入 IPv6
  的**另一**入口）。该处与「主机地址录入」无关，故 E03-2 的主结论不变，仅「唯一」二字被删。
- **本档不主张这是缺陷**：产品是否要求支持 IPv6 字面量需产品决定；此处只如实登记
  「当前不可录入」，供发布前定夺。若需支持，改 `App.tsx:5475` 的正则为允许 `:` 的 IPv6 形态即可。

**其余各维均通过**：动作组不被挤掉（3.1）、标签折叠正确（3.1）、长错误不溢出且关闭按钮可达
（3.2）、面包屑全路径可读且键盘可达（3.3）、超长路径错误不溢出（3.3）、键盘全可达且焦点可见
（3.4）。
