## 0. 结论摘要

- 四人格共报告 **40+ 条发现**，经代码与行为甄别后：**真实产品问题 26 条**（P1×5 / P2×14 / P3×7）、**demo 演示层缺陷 7 条**（不影响真实路径，但影响对外演示与 PV 观感）、**证伪剔除 3 条**。
- 最伤的三处都在**核心卖点的门面**上：审批卡不写目标主机（rm -rf 没法签）、危险命令批准一键直达、⌘F 搜索框点击后焦点被终端抢回（搜索词打进生产 shell）。
- C 人格给信任评分 3/10、D 给打磨度 4/10——但两人都认可方向与理念（「逐段裁决」「已核实」标注、简报、空态文案是好东西）。低分主要来自「状态一致性」与「危险动作摩擦」的缺失，而非功能不足。

## 1. 甄别说明：demo 演示层缺陷（不计入产品问题，但建议修复）

演示模式（`ui/src/demo.ts`）与真实后端行为有偏差。以下「严重发现」经与 T9–T21 原生走查实证及代码比对，判定为 **shim 伪影**——真实路径行为相反：

| 走查发现（人格） | shim 根因 | 真实路径实证 |
|---|---|---|
| 标签切换终端内容串台、分屏输入「同播」（B 的两个 P0） | `pushOutput` 写全局单一输出流，所有会话共享 | T11 每会话独立 xterm（历史/vim 保留）、T19 分屏 whoami 只落焦点 pane，均原生实锤 |
| 接管后控制权 chip 不翻转、无「交还」入口（C 的 P0） | `set_control` 只改 shim 全局 owner，不更新会话的 `control_owner`；真实 App.tsx:1094-1106 takeover→refreshLists→chip 翻转→显示「交还 Agent」按钮（代码在） | T12 原生走查简报控制权变迁正常。**建议补一次 5 分钟原生冒烟截图此链路**（从未单独留证） |
| 审批/断开不进操作记录（C/D） | `audit_query` 返回固定种子事件 | T9/T12 原生走查审计链全程留痕（seq 连续） |
| 会话 ID 撞车 `s-demo-0002`（B/D） | `demoSeq=2` 起步与预置 staging-1 会话撞号 | 真实 sid 由 uuid 生成 |
| 导入面板裸抛 `TypeError: …filter`（A/D 的 P1） | `ssh_config_preview` 未实现落入 `default: return null`，UI 对 null `.filter` 崩 | T21 原生走查导入面板正常（t21_a/b 截图） |
| TOFU 指纹弹窗从不出现（D） | shim 未模拟指纹门 | T17 原生走查 TOFU 全流程实锤 |
| Ctrl+C/↑↓/未脚本化命令零反馈（B） | 假 shell 只回显键入 | T10 原生走查 ^C/top/历史全过 |

**但两条真实教训从中提炼**：① UI 把后端异常原文渲染给用户（`TypeError` 直接上屏）——任何契约违例都会变成「工程师调试信息」面对用户，应转译为人话+空态兜底；② 演示模式是对外门面——**若 PV 或演示场景使用浏览器版，上表 shim 缺陷会被误读为产品缺陷**，建议按清单修复（preview 实现 / set_control 更新会话 / audit 动态追加 / demoSeq 避让 / 按会话隔离 screen / 占位反馈 / TOFU 模拟）。

**证伪剔除**：①「亮色主题对比度 2.6:1 不可读」（D）——主控复切实测切换正常、对比度 14.4:1，系测量方法误伤；②「串台/同播/ID 撞车」作为产品缺陷——见上表。

## 2. 真实产品问题清单

### P1 — 建议 PV 前修复（信任与安全）

**[P1-1] 审批卡缺目标主机/来源会话/目的——rm -rf 级裁决缺最关键上下文**【C】
卡上只有 Agent 身份、命令原文、分段裁决，不写「在哪台机器上执行」。右栏是全局审批区，多会话并存时参与者无法签字。代码实证：数据模型含 `session_id`（App.tsx:36）但卡片只渲染 `Agent：{a.agent_id}`（App.tsx:1495）。
建议：卡头加一行「目标主机 · 会话 · 目的」。
证据：[c_approval_no_host.png](screenshots/c_approval_no_host.png)

**[P1-2] ⌘F 搜索框点击后失焦，搜索词打进生产终端**【B，主控代码实锤】
⌘F 打开后直接打字一切正常（autoFocus 路径）；但鼠标点击搜索框的瞬间，焦点被终端抢回——输入逐字符落入 shell 输入行，回车即执行。~~根因：焦点委托挂在 `#term` 的 mousedown（App.tsx:729-739），`.term-search` 浮层在 `.term-session` 内~~（**2026-10-01 修复时勘误**：真实根因是 `.term-wrap` 上的 **click** 监听（App.tsx 原 499-505 行）——`.term-search` 与 `.term-settings` 两个浮层都是它的子元素，点击冒泡到 wrap → `xterm.focus()` 抢焦；autoFocus 路径无点击故正常。T16 走查只测了键盘路径，未覆盖点击）。**「安全动作」变「危险动作」。**
修复（v1.15，验收 §5.17）：click 监听排除 `.term-search, .term-settings`；同根因的设置面板抢焦一并修复。
证据：[b_search_focus_steal.png](screenshots/b_search_focus_steal.png)

**[P1-3] 危险命令「批准」无摩擦**【C】
实心绿「批准」位于最顺手位、一键直达；两段全部「未命中任何允许规则」（系统完全不知道安不安全）也不提高门槛。与「危险动作默认拦截」理念相悖。
建议：全 pending / 命中危险模式时批准需二次确认；默认焦点落「拒绝/编辑后批准」。
证据：[c_approval_no_host.png](screenshots/c_approval_no_host.png)（同卡可见三键权重）

**[P1-4] 主机无编辑、无删除**【A】
hover/单击/双击/右键均无入口。填错一条脏数据永久留在列表。PRD FR-2 承诺「增删改」。
建议：卡片 hover 出编辑/删除（删除需确认，提示「已有会话将断开」）。
证据：[a_addr_no_validation.png](screenshots/a_addr_no_validation.png)（乱码主机无法清理）

**[P1-5] 关闭已连接标签 = 静默断开会话，无确认**【B】
点 ✕ 标签即断生产连接且不可恢复（重连即新现场），iTerm 惯例是有运行进程时警告。
建议：确认弹层或「仅关标签不断会话」选项。
证据：[b_close_tab_disconnect.png](screenshots/b_close_tab_disconnect.png)

### P2 — 日用摩擦

**[P2-1] 键盘可达性两处实锤**【D，主控复核】
① 终端标签 `.tab-label` tabIndex=-1（DOM 实证），24 站 Tab 遍历永远到不了——键盘用户无法切换会话，⌘1-9 仅 tooltip 可发现；② Esc 关不掉「显示设置」面板与导入面板（实测 Esc 后面板仍在）。会话卡本身可聚焦（T11 修复仍在）。
建议：标签 tabIndex=0 + Enter 切换；所有浮层统一 Esc 关闭。

**[P2-2] 首屏自相矛盾：左栏「prod-1 · 已连接」+ 双标签挂着，终端区却说「暂无接入的会话——从左侧连接主机」**【A/B/C/D 四人格共识】
新用户前 30 秒被可见事实打脸；且「点标签不接入、必须点侧栏会话卡」不可发现。
建议：默认激活第一个已连接会话；或文案改为「点上方标签继续」；点标签即接入。
证据：[home_contradiction.png](screenshots/home_contradiction.png)

**[P2-3] 添加主机表单三连**【A】
① 字段只有 placeholder 没有常驻标签，填完值分不清哪格是哪格；② 地址零格式校验（200 字符乱码保存且「连接成功」——校验强度与端口倒挂）；③ 切换认证方式后旧错误残留（Agent 模式提示「请输入密码」）。
证据：[a_stale_error.png](screenshots/a_stale_error.png)

**[P2-4] AGENT 接入（MCP）区是死胡同**【A/C】
一行「opencode（演示） opencode」（名称还重复两遍），不可点、无端点、无 Token、无接入示例、无添加/吊销。「Claude Code 5 分钟接入」是核心卖点，入口信息量为零。
建议：说明行 + 「接入新 Agent」→ 端点/Token/可复制配置片段。
证据：[a_agent_deadend.png](screenshots/a_agent_deadend.png)

**[P2-5] 「接管并停止任务」零结果披露**【C，主控代码实锤】
核心返回值（frozen/paused_queue/stopped 逐条结果）被 UI 丢弃（App.tsx:1099-1102 只 invoke 不渲染）。「停止失败比不停止更危险」，PRD FR-6 要求逐条显示不谎报。
建议：点击后展示停止清单并回填真实结果。

**[P2-6] 连接失败反馈与操作位置断裂**【D】
prod-2 失败横幅只在中栏顶部（离点击一屏远）；主机卡无「连接中/失败」态；无下一步指引。
证据：结构性成立（demo 瞬时失败放大了无 loading 的问题）。

**[P2-7] 死会话视觉标注与输入拦截（候选，需原生复核）**【B】
demo 下断开会话画面无遮罩/变灰、键入照常回显零警告。真实产品有 Disconnected 卡与重连（T13），但「终端画面本体的死亡标注」与「死会话输入是否拦截」未单独走查过——建议原生补测；若确实无遮罩，按 PRD「诚实语义」补。

**[P2-8] 断开会话卡「重连+断开」双按钮并存、状态词被省略号吞掉**【D】
已断开还给「断开」语义不明；「staging-1 · 已断开」截断后视觉上只剩「staging-1 …」。
证据：[d_staging_card.png](screenshots/d_staging_card.png)

**[P2-9] 命令/路径任意断行**【D】
审批卡长命令在路径中间断行（`/tmp/ ↵ build.tgz`）——路径是语义载荷，断行误导。
建议：按 token 断行 + hover 全文浮层。
证据：[d_cmd_break.png](screenshots/d_cmd_break.png)

**[P2-10] 简报三层认知状态无视觉标识、控制权 fact 截断**【C】
「已确认/待核实/无法观察」的 PRD 分层没有对应文案/配色标识（「已核实」有绿标是好起点）；控制权 fact 行截断无 tooltip，且与顶栏表述不同源。
建议：每行加来源徽标（已核实=绿/Agent 陈述=灰/未知=空标）。

**[P2-11] 传输面板「下载在上方填远端路径」指代不明**【A】
「上方」= 屏幕底部命令框，隔了一整屏，且未连接时命令框提示语与下载毫无关联。

**[P2-12] 标签栏 ＋ 不是新标签，是打开「添加主机」表单**【B】
浏览器/iTerm/tmux 惯例 ＋=新标签；且表单展开后残留不收回。
证据：[b_plus_adds_host.png](screenshots/b_plus_adds_host.png)

**[P2-13] 手动「断开」无二次确认**【D】
一键断生产会话（与 P1-5 同类摩擦）。

**[P2-14] 命令框无 ↑ 历史召回**【B】
逐条执行是核心交互，连续执行必须重新点回输入框。
