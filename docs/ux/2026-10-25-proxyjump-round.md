# 2026-10-25 ProxyJump（跳板机/多跳）轮 · UX 台账

定位：连接省心梯队的第二项（FR-9 从 V2 提前立项）。跳板机引用既有主机条目（复用凭据/TOFU/编辑/审计，无内联凭据），逐跳出示指纹确认与 2FA（卡面标注「第N跳·跳板机」），失败文案点名跳板；被引用的跳板机不可删除。

界面落点：
- 主机表单（新建/编辑对话框）新增「跳板机（可选，经其转发连接）」下拉（`jump-select`）：候选排除自身/「本机」/链路绕回自身的主机（成环 UX 前置，后端 upsert 同门兜底）；保存后主机卡名称旁出「跳板」徽章（title 显示跳板名）。
- 指纹确认卡：跳板卡标题「首次连接确认（第1跳·跳板机）」，正文改写为「经跳板连接目标前，须先信任跳板主机 …」；目标卡保持原文案。双因素卡标题同样追加（第N跳·跳板机）。
- 删除保护：删除仍被引用的跳板机 → conn-error 横幅点名「跳板机正在被主机引用（…）」（与凭据删除保护 DF8.4 同款语义）。
- 快速连接与 `~/.ssh/config` 的 `ProxyJump` 指令导入 V1 不支持：导入面板该行保持不可勾（阻断级），快速连接表单不出现跳板项。

门序与焦点（连接心理学不变式）：同链多跳的门按 FIFO 排队（先跳板后目标）；gatesBusy 判定从「host_id 不同即他机门」升级为「attempt_id 不同才算他机门」——跳板门卡属于本 attempt，不再误判为别的主机在问而抑制切焦点。

验证：spec 57（13 断言）+ 全套 802/802；Rust 侧 vault roundtrip / core 守卫（环/深/缺失/本机/自引用/删除保护）/ transport 自跳 e2e（门序 hop→target、链上 shell、失败归因）+ core 自跳 e2e（TINYSSH_E2E_SSHD 门控）+ Ascend 真机自跳（#[ignore] + env 门）。
