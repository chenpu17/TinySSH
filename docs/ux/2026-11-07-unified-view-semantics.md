# 统一视图语义：主视图 × = 分离 tmux 回 shell（2026-11-07）

## 背景

用户反馈：一个标签页里并排多个 tmux 子窗口时，第一个（主视图）没有右上角按钮。先补了「放大 + ×」，但用户指出一般用户会认为 × 只关闭这个子窗口，实际却会关闭整个标签/会话——这是危险的误导。随后用户提出更根本的问题：**为什么一个标签页窗口里一定要区分哪个是主视图？**

## 结论

架构差异仍然存在：标签 = SSH 会话的主 PTY（shell、命令块、SFTP、监控、Agent 都挂在它上面）；tmux 格子 = 同一连接上的附加客户端通道。但这是实现概念，不上升为用户概念。

UI 统一为「视图」语义：

- **所有可见窗格的 × 只关闭当前视图。**
- tmux 格子 ×：拆掉该格的客户端通道（原有行为），tmux 会话继续运行。
- 主视图挂着 tmux 时 ×：只分离主 PTY 的 tmux 客户端，回到 shell；标签、面板格子、远端 tmux 会话都不受影响。
- 主视图没挂 tmux 时：没有可单独关闭的视图，不显示 ×（关闭整个会话仍走标签上的 ×）。
- 去掉「主视图」徽标；主视图标题栏与格子同款：名称 + 放大/还原（挂 tmux 时多一个 ×）。
- 标签 × 是唯一的「关闭整个会话」入口，确认框继续说明面板格子一并关闭视图、tmux 会话仍在远端运行。

## 实现

- core `tmux_detach`：`list-clients` 定位客户端；唯一客户端用 `detach-client -s <client>` 精确分离（用户改过前缀也成立）；多客户端回退向主 PTY 发前缀 `d`（tmux 默认 C-b），只拆本视图、不碰别处终端；成功后清 `tmux_attached` 记录并审计。
- Tauri command `tmux_detach`；UI bridge 与 demo 域同步镜像。
- 主视图 × 只在 `.pane-tag.tmux-attached` 下显示；分离成功后刷新清单，名牌回主机名、× 收起。
- 回归：`75-main-view-controls`（20 断言）、core `tmux_detach_clears_attach_and_targets_client`、`63-tmux-panel` / `73-focus-pane-memory` / `30-split` 定向回归。

## 边界

- 分屏模式保持原样：名牌不新增交互面。
- 主视图未挂 tmux 时不显示 ×，避免「点 × 关整个标签」的误导。
- tmux 前缀被改且存在多客户端时，回退路径可能不生效；唯一客户端路径不依赖前缀。
