# 文件面板开合致「屏幕错乱」排查轮（2026-10-30）

## 用户报告

点工具栏「文件」后终端画面错乱：claude code 的对话框内容被纵向涂抹复制（teal
色块横条、叠影边框、重复选项行），tmux 状态行完好。窗口 1998px 宽、tmux 已接
入（t-01/t-02，claude code 在窗格里等权限对话框）。

## 排查路径（四步复现梯度）

1. **窄窗口（1165px）+ vim**：文件面板走「空间不足——完整视图」覆盖模式（不改
   终端宽度），复现不出——顺带证明覆盖模式天然免疫。
2. **收主机栏进侧板模式 + vim**：宽度真变了、tmux 重绘，vim 帧完好——vim 收
   SIGWINCH 全屏重绘，几何错位不存在。
3. **ink（claude 同框架）复刻**：测试机 `npm i ink react`（npmmirror）+ 30 行
   mini-claude（色块头栏/圆角对话框/选项列表/页脚/800ms tick 重渲染），tmux 里
   跑起来后**单次开面板即复现**：青色横条（= 用户截图的 teal 块）、叠影边框、
   旧选项行残留，与用户截图拓扑完全一致。
4. **capture-pane 服务端取证**：pane 里抓到两条 frame 头（旧帧 + 当前帧）——
   残骸在 **ink 进程自己的 tty / tmux pane 里**，不在我们的渲染层。

## 根因（非我方 bug）

ink 重绘 = 光标上移 N 行再逐行重写，N = 当前帧在**当前宽度**下的行数。宽度一
变，旧帧的换行数对不上 → 上移不足 → 旧帧残行留在 pane。claude 停在权限对话框
等输入、不重绘 → 残骸永不自愈（持续输出的 TUI 只保当前帧干净，残骸留在上方）。
同款错乱是 VS Code/iTerm 侧栏开合 + claude code 组合的已知现象。我方字节流全
程无辜：tmux chrome 与当前帧渲染始终完好；PTY 日志（set_session_logging）可证。

## 恢复手段

claude 里按 **Ctrl+L**（claude 的清屏热键）让它清屏重画；或答完当前对话框/敲
任意键触发 claude 重绘——残骸行不再影响交互，只是难看。

## 设计取舍（待拍板）

文件面板宽窗口默认**侧板挤压**（现状）= 必然改终端宽度 = 必触发 claude 类 ink
应用残骸。可选：宽窗口也走覆盖层完整视图（永不改宽度，代价失去终端+文件并排）；
或加设置项/记住用户选择。

Ctrl+L 可恢复、侧板并排价值保留），不改覆盖层、不加设置项。
