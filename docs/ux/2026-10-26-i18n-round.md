# 2026-10-26 界面语言轮（i18n V1）· UX 台账

## 方案：字典反转 t()

**中文原文即键**——`t("设置")` 在 zh 下原样返回，en 下查 EN 表命中译 "Settings"、查不到**透传中文**（铺开是渐进的，缺口如实显示中文，不虚构半截翻译）。默认 zh：全部既有 spec 的中文断言零扰动。

- **带参**：`t("已保存「{0}」·", label)`——zh 键含 `{0}{1}` 占位符（渲染时必被替换），EN 同构。解决模板串：原来 `` `已复制${what}` `` → `t("已复制{0}", t(what))`（what 本身也是文案，先内层 t）。
- **刷新语义（关键决定）**：locale 是 App 的 state，`changeLocale` 写 t() 模块态 + 触发全树重渲染——渲染期 `t()` 调用重读模块变量。**不 remount**：xterm 实例与会话原样保留，切语言不打断终端。全仓唯一 memo 组件（agent-view 的 AssistantMsg）不在 chrome，无需处理。
- **铁律：模块 import 期不得调用 t()**——PALETTES/TERM_FONTS/APPEARANCES 等数据表的 label 存原中文，在渲染期消费点套 `t(p.label)`；app-data 的**取值函数**（stateLabel/phaseText/auditLabel/decisionLabel/exitText/epistemicLabel/stopOutcomeText/settingsCatLabel/friendlyError）只在渲染期被调，内部套 t() 安全。`LOG_ACTION_OPTIONS` 是模块 init 期用 auditLabel 预计算的——消费点（activity-log-panel）补 `t(o.label)` 兜住。
- **持久化**：`ui.v2.locale` 走既有 settings KV 通路（真实域 vault / demo 域 persistSetting 的 localStorage）+ t() 模块初值从 localStorage 即时读（en 启动首帧就是英文，KV 装载后不一致时以 KV 为准）。与字体/色板同工艺。
- **词表纪律**：EN 表键唯一（TS1117 兜底）；同 zh 串不同语境冲突时择一存活（「会话」→"Sessions"（palette 组名胜出），OSC52 卡回退词改用「该会话」避让；「传输」→"Transfers"（状态栏 chip 胜出，欢迎页步骤标签随大））。当前约 **430 词条**。

## 语言切换入口

设置 → 外观「界面语言」下拉（中文（默认）/ English），切换立即生效；描述行如实注明「界面铺开翻译中，未覆盖文案保持中文」。

## 实现坑

- **copyBlock 参数名撞 t**：原 `(t, what)` 双参全撞 i18n 的 t——改 `(text, what)`，且默认参 `"命令"` 保持 zh 原文、在 toast 处 `t(what)` 翻译（默认参在调用期取值，改动它会破坏 BlocksPanel 无参调用的语义）。
- **cargo/Playwright 不并发**之外的新坑：**heredoc 塞大脚本会被截断**（Bash 工具 here-doc 输出超限静默截半截，node 语法错才暴露）——大替换脚本一律 Write 工具落盘再执行。
- **CRLF**：仓库 tsx 是 CRLF，node 批量替换的多行 search 串要按 `\r\n` 自适应，单行替换不受影响——同一脚本「单行全中、多行全不中」就是它。
- **demo 主机名是数据**：「本机」作为 host name 出现在卡片上属用户数据不翻译；节头（chrome）才译。spec 断言钉节头 `[data-testid="local-host-section"] h4`。
