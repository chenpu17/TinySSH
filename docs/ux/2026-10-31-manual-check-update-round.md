# 手动检测更新轮（2026-10-31）

用户问「设置里有独立的检测升级与执行升级功能吗」——盘点现状：执行升级有
（设置→关于条件出现的「自动更新」钮），检测升级只在启动时自动跑一次、无手动入口。
用户拍板「加上」。纯前端，Rust 零改动。

## 落地

- **入口**：设置 → 关于 → 「检测更新」按钮（`about-check-update`），常驻
  （不依赖更新行出现）；副注「启动时也会自动检测一次」。
- **结果三态如实**（复用 check_update 永不抛错契约：网络失败折算 hasUpdate=false
  + error）：
  - 有新版 → info toast「新版本 v{0} 已发布」带「打开发布页」动作，且结果写回
    `updateInfo`——更新行（含自动更新钮，若 supported）即时出现在按钮上方；
  - `error` 非空 → err toast 原文（真实环境如 GitHub 不可达时如实呈现）；
  - 干净无更新 → ok toast「已是最新（v{0}）」——**带版本号**，与自动更新的
    「已是最新版本」文案区分。
- busy 态「检测中…」防连点。

## 镜像一致性修（demo check_update.current）

demo 镜像原回 `current: "0.0.0"`（占位）——此前无消费方，本轮 toast 报版本号后
暴露：关于卡显示 v0.10.6、检测却说 v0.0.0。改吃 `APP_VERSION`（与关于卡同源
package.json），镜像不再说假话。
