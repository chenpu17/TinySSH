# TinySSH 视觉升级方案与实施记录

> 起始日期：2026-11-24。目标平台保持 Windows 第一，兼顾 macOS、Linux 与 Android。
> 本轮只改变呈现层：不调整 SessionApi、term-core、审批链、快捷键与功能语义。

## 方向

**克制、精密、终端优先。** 终端内容是主角，应用外壳负责建立秩序、反馈状态；
新应用图标的紫罗兰只用于主操作、当前选中与焦点，不把界面做成紫色渐变展台。
明暗主题、17 套配色族、护眼与墨水屏都必须保留，不能只为默认深色主题设计。

### 非目标

- 不为“简洁”删除低频功能或改变既有肌肉记忆；
- 不在终端输出区加玻璃、渐变、阴影或装饰动画；
- 不从 xterm 反推状态，不改变 term-core 唯一真源；
- 不用一次性大改版同时重写导航、组件与主题。

## 已完成：品牌与图标语义轮

### 应用图标 v2

- 延续「人写提示符，机器回块」：白色 `>` + 紫罗兰块状光标；
- 圆角矩形升级为 n=4 超椭圆 squircle；提示符加粗、光标块放大并加克制磷光；
- 覆盖 macOS / Windows / Linux 图标、Windows Store 图形与 Android 五档密度；
- Android 自适应前景使用透明底纯字形，背景固定品牌深色，安全区内缩放；
- `ui/index.html` 与两个品牌页 favicon 使用同一应用图标。

权威生成源为 `scripts/make_icon.py`（4× 超采样）。完整重建顺序：

```bash
python3 scripts/make_icon.py
cargo tauri icon src-tauri/icons/app-icon.png
python3 scripts/make_icon.py   # 恢复 Android 定制 PNG 与自适应背景/XML
```

### 软件内图标

统一为 24×24、2px 圆角描边、`currentColor`。通用方向、关闭、复制等语义词可以复用；
领域入口与具体动作必须避免同形异义。新增 22 枚语义图标，重点修正：

| 功能 | 旧问题 | 新语义 |
|---|---|---|
| 跨主机编排 / 端口转发 | 共用 shuffle | 多节点网络 / 端点路径 |
| 设置分类 | 星标=凭据、刷新=审计、时钟=关于 | 钥匙 / 历史 / 信息等专用图形 |
| 快速连接 / 本地终端 / tmux | 共用终端 | 链接 / 终端 / 窗格网格 |
| 命令面板 / 搜索 | 共用放大镜 | Command / 放大镜 |
| 粘贴 / 复制 | 共用复制 | 剪贴板 / 复制 |
| 配置导入 / 文件上传 | 共用上传 | 文件导入 / 上传 |
| 定位终端目录 / 另存为 | 终端 / 收件箱 | 定位准星 / 保存 |

同一功能跨欢迎页、工具栏、专注模式保持同形；搜索、刷新、复制文件名与复制路径等
真正同义的复用保留。

验证：`npm --prefix ui run build` 通过；应用图标已检查 16–512px 深浅底、Android
方形/圆形/自适应前景。未跑完整 UI 套件。

## 第 1 轮：视觉底座（首批已落地）

先统一规则，不改功能位置：

- 色彩角色：工作区、面板、浮层、弱/强边框、主/次文字、品牌与语义状态；
- 4px 间距梯度，控件 / 卡片 / 对话框分层圆角；
- 按钮、输入框、菜单、标签、面板标题的统一尺寸与内边距；
- hover / pressed / selected / focus-visible / disabled 的一致反馈；
- 菜单与面板 120–160ms 轻过渡，尊重 reduced-motion；
- 阴影只用于浮层，不用于堆砌面板层级。

## 第 2 轮：主工作台（首批已落地）

- 标签栏：当前会话明确，状态信息次要，关闭操作降低噪声；
- 主机卡片：名称/地址为主，徽章与操作后退，键盘焦点不丢失；
- 会话工具栏、左右面板与状态栏：统一标题、间距、分隔与选中态；
- 分屏/tmux：活动窗格边界清楚，非活动区域适度后退；
- 不移动核心入口，不删除功能，不改变终端尺寸计算语义。

## 第 3 轮：专业视图（浏览器 demo 已落地）

设置、命令块、SFTP、记录、监控、协作/Fleet 与 tmux 大屏沿用同一组件语言；空状态提供明确
下一步，危险色只用于危险与失败，监控图表保持一致的状态色与非颜色提示。

## 第 4 轮：全平台验收（浏览器矩阵与 Android 模拟器已完成，原生桌面待验）

- 默认深色、浅色、护眼与墨水屏逐项检查；
- UI 80–125%、舒适/紧凑密度、键盘导航与焦点可见；
- Android 安全区、触控目标、横屏/平板与外接键盘；
- 终端逐帧采样前后对比，禁止为视觉效果引入持续重绘；
- 每轮保留验证记录，未实际验证的项目不得标为完成。

进度：浏览器矩阵（2026-11-25）与 Android 模拟器（2026-11-26~27）两部分已做，记录见实施记录对应两节；

### 2026-11-25 · 终端优先与 Agent 后退

用户反馈 Agent 对话与 Fleet 编排过宽、专注模式右上角接管/停止等按钮过多、tmux 四宫格缺少领域识别。
本轮据此继续收敛为「终端是主角，Agent 按需出现」，不删除功能或改变安全语义。

- **Agent/Fleet 共用窄栏**：实测两者默认均为 420px；现降为 **340px**，拖拽范围由 320–560 收敛为 **300–440px**。
  宽度常量、初始读取、拖拽计算、持久化恢复与中英文 aria/title 使用同一口径；旧持久值只在读取时钳到新边界，

### 2026-11-27 · 重确认横幅改为一次性提示

- **来源**：用户在原生应用（v0.12.32）上反馈——SSH 会话重连成功后，「ⓘ 已重连；旧现场待核实——你可以
  继续操作。」这条横幅一直在，占用显示空间（KI-137）。
- **原因**：状态机按 §6.4 走——重连成功后进入 `Reconfirming`，直到人类在新连接上提交第一条命令
  （终端回车 / 命令框 exec）才回 `Connected`，没有自动核实。问题在呈现：这期间 `App.tsx` 常驻一整行
  琥珀横幅，浏览器 demo 实测高 27px，把标签条顶边 38→65、终端顶边 112→139，出现与消失各让终端
  重排一次；盯着输出不敲回车时它就一直挂着。而同一状态本就有两处常显——标签琥珀点、工具栏状态
  胶囊「已重连 · 待核实」，横幅是第三份。
- **改动**（仅前端，状态机 / 审批链 / demo 未动）：删除常驻横幅与 `.notice-bar.warn` 规则；当前会话
  进入重确认的那一拍弹一条 info toast（6 秒自动消失、可点 ×），文案沿用原句（`reconfirmNote`，
  Agent 掌控时多一句「Agent 已暂停（普通变更仍受限）」）；工具栏状态胶囊加 `title` 悬停显示同一句；
  标签琥珀点不变。只认状态迁移的那一拍——页面刚载入时已是重确认态的会话不补弹，同一轮里切走再
  切回不重复弹。专注模式对 `Reconfirming` 仍钉住标签条（此时工具栏胶囊是藏起的，标签琥珀点是唯一
  常显的状态）。原生 e2e 冒烟脚本 r26 的断言面从横幅换到工具栏胶囊。
