# tmux 前缀让位 + 面板拖拽布局轮（2026-11-02）

用户原话：「Ctrl+B 是tmux的关键能力按键，优先保证，如果有冲突，其他地方的先修改。另外多tmux窗口的管理，能否支持拖动，方式动态来管理布局？」

## 一、Ctrl+B 让位给终端

**病根**：Win/Linux 默认键位表 `主机栏开关 = Ctrl+B`（`keymap.ts`），控制字符直发层按「组合在表内即豁免」把它让给应用动作——主视图与 tmux 格子永远收不到 `\x02`，tmux 前缀物理键入不了（mac 主修饰键是 ⌘，⌘B 不撞）。溯源：10-14 直键轮登记过「Ctrl+F/K/B 仍归 shell」，同日键位配置轮 42c2657「表内全豁免」把它翻了。

**落法（「其他地方先改」）**：

1. `defaultKeymap(mac)`：mac 主机栏仍 ⌘B；Win/Linux 改 **Ctrl+Shift+B**（Windows Terminal 惯例：应用动作走 Ctrl+Shift，Ctrl+字母留给 shell）。
2. `terminalReserved`：Win/Linux 的 Ctrl+B 列为终端保留键——
   - `parseKeymap` 载入即回落默认：录键器是整表落盘，旧版用户存量串里的 hostbar 必是 Ctrl+B，走此分支即迁移（同表其余改绑原样保留）；
   - 录键器拒收，toast「Ctrl+B 留给终端（tmux 前缀键），请换一个组合」，保持录入态；
   - 直发层豁免判定收口为 `exemptFromTerminal`：保留键无条件不豁免——表里混进旧值也不吞 tmux 前缀（防御纵深，单测钉死）。
3. 提示文案动态化：命令面板 hint 与主机栏收/展钮 title 原硬编码 `⌘B`/`⌘F`（Windows 上也显示 ⌘），改按当前键位表 `formatBinding` 渲染。

**如实列出、本轮未动的同类冲突**（默认表里与终端控制键重叠的另外五个，均为既往轮次拍板的行为，用户只点了 Ctrl+B）：Ctrl+D 分屏（shell EOF）、Ctrl+W 关标签（readline 删词）、Ctrl+K 命令面板（删到行尾）、Ctrl+F 搜索（光标右移）、Ctrl+T 新建连接（交换字符）。tmux 另一常见前缀 Ctrl+A 不在表内，天然直达。

## 二、面板拖拽布局

**交互（寄生既有元素，零新增控件）**：

- **拖分隔条调大小**：格子间的竖/横线 8px 命中区（静态分隔线仍是格子 1px 边框，条只在悬停/拖动时亮 accent），两侧各守最小 180×100px；双击分隔条 = 该组均分。与分屏分割条同手感（拖动中 150ms 校准一次 PTY 几何，松手校准终态）。
- **拖标题栏换位**：格子标题栏与主视图名牌都可抓（grab 光标 + title 提示），5px 阈值区分点击与拖动。落在目标格**中央 = 互换**，落在**四边 = 目标对半分开、被拖格占那一半**；拖动中被拖格半透明，落点提示框**预演落下后被拖格的真实位置**（所见即所得——被拖格原位的空间先还给邻居，目标格再对半）；Esc 取消。
- 右键菜单「重置面板布局」（仅布局被拖过时出现）→ 回到自动平铺。

**模型**：`pane-grid.mjs` 嵌套行/列树（叶 = 主视图 `:main` 或 tmux 会话名；容器 row/col + 子节点权重），纯函数零依赖：`defaultLayout`（与 `paneGrid` 逐格同几何——没拖过的用户零感知）、`layoutRects`（几何 + 分隔条）、`moveTile`/`insertBeside`/`swapTiles`/`removeTile`/`syncLayout`/`resizeAt`/`equalizeAt`/`dropZone`；规范形（容器 ≥2 子、同向摊平）每次变换后收口，变换不改入参。

**语义**：没拖过 = 自动平铺（开关格照旧重排）；拖过 = 该标签的布局树——关格时它的空间按比例还给同组兄弟，开新格从当前最大的格子里沿长边分出一半（面积并列取树序靠后者），格子全关即作废。布局按 tmux 会话名认格：掉线重建换装（新 pane_id、同名）原位不动；前端内存态，重连不丢、关标签/重启即弃。分屏期间格子隐藏、布局留着。

**顺手修**：窄格里 tmux 收尾行软折行，`lastTmuxNotice` 只读物理末行 → 「窗格已结束」toast 截成「[detached (from sessi」。改按逻辑行读（`isWrapped` 续行拼回）。拖拽测试把格子拖窄后才暴露。

**demo 镜像**：格子输入补 tmux 前缀——`\x02` 吞下不回显，下一键是 tmux 命令（`d` = 脱离，与 `demo_pane_exit` 同款收尾），spec 63 据此用真实键盘验 Ctrl+B d。

## 教训

1. **键位豁免只在 Tauri 域生效，demo 永远测不出**：UI 套件全绿≠真机可键入。保留键判定抽成纯函数 + 单测钉死 + 真机键盘走查，三层缺一不可。
2. **WebView2 同一用户数据目录、不同启动参数不能并存**（`0x8007139F`）：用户实例在跑时起带 `--remote-debugging-port` 的走查实例必须 `WEBVIEW2_USER_DATA_FOLDER` 另指目录。
3. **运行中的 exe 可改名不可覆盖**：cargo 产物是 `target/release/X.exe` 与 `deps/X.exe` 两个硬链接，都改名后再构建，不打扰用户实例。
4. **读终端缓冲按逻辑行**：窄格软折行会切碎任何按行匹配的文本（收尾提示、走查读屏同理——走查脚本自身也栽了一次：`tr` 吞掉换行让结束标记与输出同行，读屏超时）。

### 修复

- **P1 分隔条抢焦点**：拖条/双击均分后的 click 冒泡到 `.term-wrap` 的「点空白聚焦主终端」——排除表只有 `.tmux-cell` 没有 `.tmux-div`，焦点从格子被抢到主终端，接着打的字进主视图。排除表补 `.tmux-div`。
- **P2 拖动态卡死（两处同形）**：拖动中被拖的格子/分隔条所在树形被删（远端结束、重建换装）——元素移除后 `lostpointercapture` 派发到 document，元素自己的监听收不到：全窗光标锁成 resize/grabbing、提示框残留、Esc 监听吞掉下一个 Esc（vim 用户的 Esc 被吃）。修：排版后 `sweep` 核对被拖者仍在、分隔条删除时先收尾、move 里 `isConnected`/`buttons` 守卫、窗口级 pointerup 兜底、按下时记树形签名（拖动中开关格改了树形即收尾，防 path/index 指向别的边界）。
- **P2 重建换装后焦点落主终端**：掉线重连原位换装是「先收旧格（握焦点→兜底交还主终端）再建同名新格」——记交接意图，排版后焦点交给同名新格（只在焦点仍停在兜底主终端时，5s 内有效）。
- **P2 键位两遍解析**：旧 `parseKeymap` 逐条与「尚未覆盖的默认值」比较——主机栏已改 Ctrl+H 而命令面板用 Ctrl+Shift+B（新默认键）、或合法对调两个键，重载即被误丢回默认。改为先收合法自定义、再补默认，冲突按终态判；默认值与自定义撞键时默认优先、该自定义回默认（迭代到稳定），**一次性 toast 交代（附「去设置」）并回写**，下次不再提示。
- **P2 单条「重置」撞键**：默认键已被别的动作改占时直接落出两条同键的表（分发只认先命中者）。改宿主 `resetKeyBinding` 校验，冲突拒绝并指明占用者（冲突提示里的动作名也补了 `t()`）。
- **P2 提示文案漏改**：rail「连接（⌘B）」在 Windows 上显示 ⌘B（实为 Ctrl+Shift+B）；同类的工具栏「搜索（⌘F）」「分屏（Ctrl+D）」、命令面板钮「Ctrl+K / ⌘K」一并改为按当前键位表渲染。键位页说明补「Ctrl+B 始终留给终端（tmux 前缀键），不可占用」。
- **P2 嵌套格最小尺寸**：`minExtent` 同向容器用求和——比例不均时拖外层分隔条能把内层窄格压到最小值以下（反例 B=90px<180px）。改按「子格保持占比整体缩放」反推 `max(子最小值/子占比)`；放不下两侧最小值（窗口太小）时不再锁死，只许让偏小一侧变大的移动。另：`resizeAt` 缺省 min 不再产出零宽格、非整数下标原样返回、非法落点拒绝、权重每次规范化归一（同轴开关格数千轮后下溢成 0）、删掉与真实落点不一致且无人用的 `zoneRect`。
- **P2 探针校正（Rust）**：tmux_attached 残留校正按「探针返回时刻算年龄」——exec 慢回时年龄过期而快照仍是注入前的旧景，会清掉合法 attach。改按**探针发出时刻**比较（教训同上一轮的「快照请求时刻晚于出生才认缺席」）。
- **P2 开格 × 主视图 attach 互穿（Rust）**：两道防呆各自在 await 前核验、await 后登记/置位，可被同时穿过（同一会话主视图 + 格子两路视图）。改为 attach 侧「核验清单 + 预占 tmux_attached」同一临界区、开格登记段复核 tmux_attached（锁序 panes → wishlist → tmux_attached 一致），写入失败回滚预占。**修时自揪一处**：`tmux_switch_client` 从 tmux_attached 读「当前会话」去找 client——预占后读到的会是目标名，改为调用方显式传入原会话。
- **P3**：分隔条按相对位移拖（单击 1px 抖动不再让边界跳到指针处）；拖拽按 pointerId 收尾（第二根指针不结束第一根）；标题栏/名牌 `touch-action:none`；分隔条按下防重入；分屏期间主视图右键不给「重置面板布局」；格子 OSC 52 询问卡标出 `tmux:会话名`；面板写入时限注释如实（单块时限非严格无进展）+ `close()` 先置 alive=false、写循环块间即停（关格最多等一块）；`shortcuts-keys` 单测钉死平台（mac 上跑会走 ⌘ 口径）。
- **DEV 豁免钩子**：两路审查都指出「spec 的 Ctrl+B 断言在 demo 里恒真」——直发层豁免分支只在 Tauri 域进入。加 `window.__t_keymapExempt`（`import.meta.env.DEV` 门控，release 包 0 处残留已核）让 demo 走同一分支；但 demo 的动作分发只认 ⌘（native 门），故 spec 只能验「路由」（表内组合不发往终端、保留键直达），动作触发仍由单测 + 真机键盘守门——如实写进 spec 注释。

### 教训（本轮新增）

5. **跨路径互斥要「核验 + 预占」同一临界区、同一锁序**：一边 await 前核验、await 后登记，另一边同理，两道防呆就能被同时穿过。把置位挪到 await 之前时，**先 grep 该字段的全部读者**——`tmux_switch_client` 正是从被预占的字段读「当前会话」，挪完会去找错的 client。
6. **demo 测不到的分支，加 DEV 钩子也只能证明一半**：钩子让 demo 走 Tauri-only 的豁免分支，但 demo 的动作分发另有 native 门——spec 只能断言「路由」（发不发往终端），动作触发仍归单测 + 真机。把能证明什么、不能证明什么写进 spec 注释，别让断言标题许诺做不到的事。
7. **命令式拖拽的收尾不能只靠被捕获元素的事件**：元素被移除时 `lostpointercapture` 派发到 document——排版后核对被拖者仍在 + 窗口级抬起兜底 + move 里 `isConnected`/`buttons` 守卫，三层兜住。
8. **指针捕获拖拽结束后的 click 从捕获元素冒泡**：祖先上任何「点空白聚焦 X」的处理器都要排除拖拽把手，否则拖完焦点被抢。
9. **行尾判定用 Node 量，别信 Git Bash 下 ugrep 的 `$'\r$'` 计数**（本轮误判过一次，变异锚点因此首轮落空）。
