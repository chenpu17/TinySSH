# GBK 支持 UI 入口走查 —— 老系统维护者视角

- 走查人角色：老系统维护者（手里有中文 Windows 和老旧设备，终端编码 GBK，最怕连上去中文乱码）
- 环境：demo UI http://localhost:5183（浏览器 demo 模式），视口 1280x800
- 范围：仅 UI 入口（真实编码转换在 Rust 层，不在本轮范围）
- 截图：/tmp/pv_gbk_*.png

## 走查结论

**总体：PASS（核心链路 4 项全过），2 条建议。**

作为一个天天跟 GBK 老机器打交道的人，我最关心的三件事——「默认别给我乱来」「选对了我能看懂」「保存了别丢」——全部满足。真正让我皱眉头的是两件小事：下拉框收起后字被截得只剩两个字母；主机列表里完全看不出哪台是 GBK 机器。

## 逐项验收

### 1. 添加主机表单「远端编码」下拉：默认值与文案 —— PASS

- 证据：/tmp/pv_gbk_01_form_default.png + DOM 导出
- 默认选中 `utf-8`，选项文案为：
  - `UTF-8（默认）`
  - `GBK（中文 Windows / 老旧设备）`
- 评价：默认 UTF-8 正确——新机器/云主机绝大多数是 UTF-8，不该让大多数人为少数人付成本。GBK 选项的说明「中文 Windows / 老旧设备」我一眼能看懂，说的就是我手里那几台财务老 Windows 和机房老设备，场景指认准确，没有术语黑话。

### 2. 新建 GBK 主机 → 保存 → 编辑表单回填 —— PASS

- 操作：新建主机「老财务机-GBK」（192.168.9.21，administrator），远端编码选 GBK，点「保存并连接」；弹出的首次连接指纹确认（TOFU）点「信任并连接」；然后点该主机的编辑按钮。
- 证据：/tmp/pv_gbk_02_form_gbk_selected.png（选中 GBK 的表单）、/tmp/pv_gbk_02b_tofu.png（首连指纹确认）、/tmp/pv_gbk_04_edit_gbk.png（编辑表单）
- DOM 实测：编辑表单中「远端编码」select value = `gbk`。选择被记住了。

### 3. 改回 UTF-8 保存 → 再进编辑回填 —— PASS

- 操作：编辑表单中把编码改回 UTF-8，点「保存修改」，再打开编辑。
- 证据：/tmp/pv_gbk_05_edit_utf8.png
- DOM 实测：「远端编码」select value = `utf-8`。双向切换都正确回填。

### 4. 列表里能否分辨哪台主机是 GBK —— 疑问（按约定不算 FAIL）

- 证据：/tmp/pv_gbk_06_list.png + 主机卡 DOM 导出
- 实测：主机卡只有名称、认证方式徽章（密码/密钥/Agent）、`user@addr:port` 三样信息，title 悬停提示里也只有地址和指纹，**没有任何编码标识**。我能认出「老财务机-GBK」是因为我自己把 GBK 写进了名字——如果我没写，半年后我绝对想不起来哪台机器改过编码。
- 真实感受：这对我是个实际痛点。乱码出现时我的排查路径是「先怀疑编码」，而列表不能告诉我「这台是不是已经设过 GBK」，我就得逐台点进编辑表单确认。建议在主机卡上加一个小徽章（比如 `GBK` 灰标），或者至少加进悬停 title（`编码：GBK`）。

### 5. 入口位置与直觉 —— 疑问/建议

- 我的真实使用路径：加主机时我**不会**想到编码这回事——我都是连上去、`ls` 一出中文目录名变乱码了，才一拍脑袋「哦这破机器是 GBK」。
- 好在发现乱码后我的第一反应是「找到这台主机的设置改一下」，编辑入口（主机卡上的铅笔按钮）符合直觉，改完重连即可，这条链路是顺的。
- 但我更希望的体验是：**在会话里能临时切**。场景：我连上一台混用的跳板机，大部分目录 UTF-8、个别老应用日志是 GBK，我不想为了看一眼日志去改主机配置再重连。建议在终端工具栏（或右键菜单）加一个「本会话编码：UTF-8 / GBK」的临时切换，不动主机配置；主机表单里的设置作为默认值。这是建议，不是阻塞。

### 6. 其他发现

- **（建议）下拉框收起态截断**：表单里「远端编码」select 收起后只显示「UT」「GB」两个字母（见 pv_gbk_01 与 pv_gbk_04，「认证方式」同样只显示一个「密」字）。UTF/GBK 靠前缀还能分辨，但说明文字完全不可见，且视觉上显得局促。建议该下拉收起态至少完整显示 `UTF-8` / `GBK` 四个字符。
- **（中性）TOFU 指纹确认**：点「保存并连接」后先弹指纹确认框再连上，流程符合预期，无问题。
- **（中性）编辑按钮 tooltip**：「编辑主机（名称/地址/端口/用户名，凭据保持不变）」的列举里没提编码，实际编辑表单里是有的。无关紧要，但既然 tooltip 在做「列举」，建议补一句「编码」或改成「编辑主机设置」。

## 给开发的问题清单

1. 主机卡是否有计划加编码标识（徽章或悬停 title）？没有的话，理由是什么？
2. 是否有「会话内临时切换编码」的规划？真实后端上编码是建连时协商还是流式可切——如果架构上只能建连时定，建议至少在会话里给出「当前编码」的可见提示。
3. 编辑按钮 tooltip 的列举与实际可编辑项（含编码）不一致，是有意省略还是漏改？
4. demo 模式下主机数据仅存内存（刷新即丢），真实持久化路径是否已有 e2e 覆盖 charset 字段的落盘与读回？（本轮按约定未验证 Rust 侧，仅确认 UI 层往返。）
