## 走查结论

**总体 PASS。** 交接信息「写得出、存得住、对方读得到、全程有留痕」这条核心链路完整闭环：种子留言正确回填、保存有即时 toast 与时间线留痕、清除有独立反馈、跨标签切换留言随会话存续。保存按钮的禁用逻辑（内容未变即禁用）做得很到位，杜绝了无意义重复保存。两处非阻塞问题见「给开发的问题清单」。

## 逐项结果

### 1. 接入种子会话：任务目标区出现 + 种子留言回填 —— PASS
- 右栏「任务目标」区块在接入 s-demo-0001 后出现，输入框回填种子留言「把 /tmp/old-build 清理掉并重新打包 dist 到 /tmp/build.tgz」。
- 输入框下方辅助文案「Agent 接管与读简报时会先看到这里；随会话结束自动消失」把用途和生命周期讲清楚了，交班人一眼知道写在这里有用。
- 证据：截图 01_seeded。

### 2. 编辑并保存：即时反馈 + 防重复保存 —— PASS
- 编辑后保存按钮从禁用变可用；点击保存，右下角 toast「任务目标已更新，Agent 读简报可见」（ok 绿色条）。
- 保存成功后按钮立即回到禁用态（内容未变），初接入未编辑时也是禁用态——防重复保存逻辑验证三个状态点全部正确。
- 保存后输入框保持新值，未被简报轮询覆盖。
- 证据：截图 02_saved；断言 `T2-save-*` 全 PASS。

### 3. 操作记录时间线留痕 —— PASS
- 保存后时间线即时出现条目：「19:27:44 · prod-1 / 我 更新任务目标 核实 /var/log/nginx 磁盘占用…」，hover title 含 `#43 goal_set · <完整目标文本>`。
- 可读性：时间戳+主机名独占 meta 行，actor「我」warn 色高亮，动作与目标文本分行，竖轨圆点 Timeline 样式下扫读顺畅。
- 证据：截图 02_saved 底部；断言 `T3-audit-*` 全 PASS。

### 4. 清除目标 —— PASS
- 清除按钮只在有目标时出现：有种子目标时 count=1，清空/新会话时 count=0，三个状态点均验证。
- 点击清除：输入框立即清空、toast「任务目标已清除」、清除按钮消失、保存按钮因「空 vs 空」保持禁用。
- 清除动作同样留痕：时间线「更新任务目标」条目从 1 增至 2（保存+清除各一条）。
- 证据：截图 05_cleared；断言 `T4-*` 全 PASS。

### 5. 跨标签切换：留言存续 + 未保存草稿行为 —— PASS（草稿行为为 INFO，如实报告）
- 已保存留言随会话存续：在另一个会话（本机 s-demo-0100）标签打了半截草稿，切回 prod-1，已保存的留言完好。
- 新会话目标为空，且清除按钮正确隐藏。
- **未保存草稿：切走再回来后草稿被丢弃**，输入框恢复为该会话已保存值（空）。对我这种老手来说可接受（留言本来就短、随写随存），但写长留言时被电话打断切出去看一眼、回来没了，会窝火。见问题清单 Q2。
- 证据：截图 03_draft_unsaved / 04_draft_after_switch；断言 `T5-*`。

### 6. 现场简报长文本换行可读（R7） —— PASS
- 「重连后进入重确认：仅内置只读白名单可用」fact 块完整换两行显示，`white-space: normal`，scrollH=clientH=36 无裁剪；「需复核」认知色徽标醒目。
- 同区「控制权：14:02:11 · 人类接管（交接前未开始的请求全部作废）」也完整换行。
- 证据：截图 06_brief；断言 `T6-long-text-wrap` PASS。

### 7. 其他发现（交接场景）
- **textarea 固定 rows=2 不自增高**：写入多步委托（约 90 字）后 scrollH=84 vs clientH=48，开头被滚出视野，交班人无法整体通读自己写的留言。交接留言恰恰容易写长（分步骤、带条件），建议自动增高或至少给 resize 手柄之外的扩容。证据：截图 07_long_draft。
- 简报 4 个 fact 块（当前目录/最近命令/重确认/控制权）+ 任务目标区配合，Agent 视角的「现场」信息完整，符合交班预期。

## 给开发的问题清单

1. **Q1（阻塞性 bug 嫌疑，主机卡点击）**：`.host-card-main` 的几何中心被悬浮操作组 `.host-card-side` 的 svg 图标遮挡，Playwright 默认点中心时被拦截超时 30s。真人鼠标虽能点到未被遮挡区域，但请确认悬浮操作组的遮挡范围是否符合预期——主机名/状态文字区域是否被覆盖？（T37 重设计的遗留边角）
2. **Q2（建议，非阻塞）**：未保存的委托留言草稿在切换会话标签时静默丢弃，无任何提示。是否考虑：切换时保留草稿（按 sid 存 map），或至少在「有未保存修改」时给个视觉提示（如保存按钮旁一个小圆点）？
3. **Q3（建议，非阻塞）**：任务目标 textarea 固定 2 行不自增高，长留言通读困难。建议内容增多时自动增高（上限 6~8 行），或至少默认给到 3 行。
4. **Q4（确认项）**：清除目标后 toast 是「任务目标已清除」，而保存是「任务目标已更新，Agent 读简报可见」——清除时 Agent 简报里 goal 也同步消失（demo 代码 `goal: bs.goal` 已确认同步），但 toast 文案要不要也点一句「Agent 简报同步移除」，让交班人确信对方不会再看到旧留言？纯文案斟酌。
