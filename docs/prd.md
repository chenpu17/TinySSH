## 1. 一句话定位

**面向远程运维、本地优先、支持不同 Agent 的人机协作 SSH 工作台。**

核心体验一句话：

> **工程师把正在处理的远程现场交给 Agent，随时介入，再把更新后的现场交还给它。**

类比：Pencil 之于网页设计（Agent 与人类共享同一画布），本产品之于远程服务器（Agent 与人类共享同一**现场**——终端画面只是现场的一部分，还包括工作目录、环境、进行中的任务与刚发生过的操作）。

## 2. 愿景

远程运维正在从「人操作终端」演进为「人监督 Agent 操作终端」。但当前两条路线都走不通：

- **无头 SSH MCP / agent 内置 ssh**：Agent 通过一次性 `ssh host "cmd"` 操作，无状态、无交互、人类完全看不见过程，凭据暴露在 Agent 环境里；
- **传统 GUI SSH 客户端**：体验面向人类，没有 Agent 通道；新起的新一代终端（Warp）有审批和外部 Agent 支持，但围绕编码场景，远程运维纵深不足。

本产品把两条路线合并：**GUI 客户端本身就是一个具备授权、审计与交接能力的 MCP Server**。如果「把远程现场交给 Agent，再拿回来」这件事做得顺畅，就有独立产品的理由。

**核心价值排序**（设计取舍的总依据）：

1. **现场连续**：人的现场（目录/环境/刚做过的事）能交给 Agent；Agent 干完的现场能交还给人。消除复制日志、口头解释环境、重复定位的成本。
2. **知情可控**：用户始终知道 Agent 获得了什么权限、正在做什么，并能有效改变它接下来的行为。
3. **本地优先**：连接、凭据、授权与操作记录沉淀在本地，换 Agent 工具不丢，形成持续使用的基础工具。

## 3. 目标用户与画像

### 3.1 第一批画像（验证阶段唯一聚焦）

> **已经在使用 Agent（Claude Code / OpenCode 等）、每周多次维护几台 Linux 服务器、愿意在关键操作时介入的开发者。**

这个人群能直接验证协作价值，且规模小、决策链短。完整 SRE 场景（批量变更、团队权限、故障恢复流程）会把产品迅速推向更重的要求，验证阶段不碰。

### 3.2 后续画像（V2 之后评估）

| 画像 | 描述 | 后移原因 |
|---|---|---|
| 运维/SRE | 批量巡检、故障处理、多机编排 | 需要团队权限、聚合视图等产品深度，验证闭环不依赖 |
| 多机管理者 | 10+ 台机器的批量操作 | 同上 |

**明确不是目标用户**：不会用 SSH 的小白、需要云同步团队主机库的团队、移动端场景。

## 4. 问题定义（用户痛点）

1. **Agent 操作远端是「一次性」的**：`ssh host "cmd"` 没有会话状态（cd / 环境变量不延续）、无法处理交互（sudo、确认提示、vim）、无法跟随长任务（tail -f、watch）。
2. **人与 Agent 之间交接靠复制粘贴**：人手里的现场（目录、环境、刚做过什么）传给 Agent 靠贴日志、口头解释；Agent 干完的现场传回给人靠读屏和猜。
3. **人类是盲的**：Agent 在远端干了什么，只有事后文字日志；出问题时无法实时介入。
4. **凭据治理缺失**：把私钥放进 Agent 的环境或文件系统 = 私钥扩散；无人留痕 Agent 在生产机上执行过什么。
5. **现有工具缺人机协作通道**：传统 GUI 客户端没有 Agent 接口；新一代终端的 Agent 能力围绕本地编码，远程纵深不足。

## 5. 设计理念（决策过滤器）

> 本节是产品的宪法。任何设计/实现争议，用以下条目裁决；违反任何一条的实现方案默认否决。

1. **单一真源**：终端屏幕状态只有一份，存在于 Rust 侧的终端仿真核心；GUI 与 MCP 都是它的视图。禁止在 JS 侧维护第二份状态真源。**澄清**：xterm.js 自身是有状态的渲染仿真器，在本架构中它是「可丢弃、可重建的渲染缓存」——必须可被真源快照整体重置（resync 协议见 L0 ADR-2），且任何查询类接口（屏幕快照、历史取回、审计取回）不得以 JS 侧缓存为数据来源。
2. **知情与可控（人类在环）**：用户始终知道 Agent 获得了什么权限、正在做什么，并能有效改变它接下来的行为。审批门、允许清单、TTL 授权窗口都是实现**手段**而非目的：授权信息以任务为中心组织（目标主机、任务目的、允许范围、当前进展、待决事项），危险动作默认拦截。**人工审批比例是健康度观察指标，不是成功指标**——授权过多说明用户被打断；但在明确且被用户理解的预授权范围内，全程免审可以是正常结果。判断依据是**是否越界**与**用户是否理解自己的授权**，而非免审频次本身。
3. **Agent 一等公民**：为 Agent 提供结构化、可预测的通路（exec-first：干净 stdout/stderr/exit code）；交互式屏幕操作（读屏/按键）是例外路径。exec 必须默认延续现场（shell 模式），否则「修复一次性 ssh 无状态」名不副实。
4. **安全默认**：最小权限、凭据永不离开客户端、全量审计、危险命令模式默认拒绝。本地 MCP 端点必须认证，且按 Agent 差异化授权（每个接入的 Agent 独立身份）。
5. **双前端对等**：MCP 的能力 ⊆ GUI 的能力；两者是同一个核心（SessionApi）的两个对等前端。核心层不感知「谁在调用」的差异；差异仅体现在 Actor 上下文与审批策略上。
6. **Rust 核心、薄壳**：全部业务逻辑在 Rust core；WebView UI 与 MCP Server 是无业务逻辑的渲染/暴露层。

## 6. 目标与非目标

### 6.1 验证版目标（V0–V1）

- **一个真实的共享会话**（SSH → Linux 服务器，bash/zsh 起步；macOS 客户端）
- **完整的交接闭环**：持久现场（cwd/env 延续的 exec）、接管契约（见 FR-6）、现场简报交还
- **任务为中心的授权**：审批卡片、逐段求值、允许清单、TTL 授权窗口
- **可理解的操作记录**：按任务/会话时间线呈现的人类可读记录
- **低成本接入**：导入既有 `~/.ssh/config` 与密钥；Claude Code / OpenCode 5 分钟接入 MCP
- 方便的技术指标 gate（IPC 吞吐、exec 延迟等）由 M0 Spike 先行验证

### 6.2 非目标（验证阶段不做，进入 V2 须修订本节）

- ❌ 多机编排、端口转发、双栏 SFTP GUI（V2）
- ❌ Windows / Linux 桌面端（V2；验证阶段仅 macOS）
- ❌ 完整终端替代体验（主题、搜索、块级 UI 打磨——V2）
- ❌ 审计浏览器的规模性能优化（V2；验证版保证正确与可读即可）
- ❌ 长期非目标：Mosh / Telnet / 串口、云同步与团队主机库、移动端、内嵌 VS Code 式远程编辑器、Agent 自主决策框架、终端录制回放

> 非目标的意义：任何 PR 试图引入上述能力而未先修订本节，视为偏离愿景。

## 7. 功能需求

> 阶段标注：**(V1)** = 验证版必须有；**(V2)** = 完整客户端阶段。
> 每条需求附验收标准（AC），AC 是阶段验收的唯一依据。

### FR-1 连接与会话管理（V1 最小集）

- 多标签会话：本地终端 + SSH 会话并存；侧栏主机一键连接
- 会话状态：连接中 / 已连接 / 断线（重连状态机：断线保留显示与记录、断点以分隔线标注；重连后进入**重确认流程**——Agent 的普通动作被阻止，仅开放**客户端内置的只读核实命令白名单**（`pwd`/`printenv`/`which`/`ps`/`systemctl status` 等，Agent 不可自选），核心依据核实结果自动判定完成（简报中 SSH 侧事实恢复「已确认」）后恢复执行）
- 终端基础体验：xterm.js 渲染、复制粘贴、字号缩放（主题与搜索 V2）

**AC**：同时开 5 个 SSH 会话 + 1 个本地 shell 无明显卡顿（以 SPIKE-1 指标为准）；断线**保留操作记录与显示历史**；重连后重确认期间普通变更动作被阻止、核实流程可自行完成；**运行中进程状态未知（nohup/systemd 任务可能仍在运行），必须核实，不得当作已结束或自动重试**；复制粘贴符合平台习惯。注意：重连保留的是显示与记录，**不等于现场延续**（原 shell 的目录/环境随连接消失）；SSH 远程会话的真正持久化（tmux 类）单独评估，不在 V0 范围。

### FR-2 主机与凭据管理（V1 最小集）

- **导入既有 `~/.ssh/config`**（主机/用户/密钥映射，导入向导）；手动增删改；分组标签从简
- 认证方式：密钥（导入 OpenSSH 格式 / 生成 ed25519 / 指纹确认）、密码、keyboard-interactive（2FA/PAM 挑战）、ssh-agent
- 凭据落盘加密（系统钥匙串保护）；私钥仅在内存解密，任何 API（含 MCP）不返回私钥明文；agent 转发默认关闭

**AC**：试点用户的真实 `~/.ssh/config` 导入后可直接连接；导出的数据文件无明文凭据；MCP 工具无法枚举/导出私钥；开启 2FA 的主机可完成 keyboard-interactive 登录。（完整主机资产管理：分组/标签/跳板链 → V2）

### FR-3 MCP Server（V1）

- 传输：streamable HTTP，绑定 `127.0.0.1` **固定默认端口**（被占递增），实际端口持久化并在 GUI 展示；stdio shim 二进制（直连同一 HTTP 端点）
- 认证：**per-client Bearer Token**——每个 Agent 接入独立签发身份，可单独吊销；审批模式由人类按 client 预配置，MCP 请求不可自选
- 工具集（完整规格见 L1 §4）：
  - `list_hosts` / `list_sessions` / `create_session` / `close_session`
  - `exec`（**双模式**：`shell` 持久会话内执行、**cwd/env 延续**，V1 默认；`fresh` 独立通道、纯结构化执行，可选）
  - `cancel_exec` / `upload` / `download`
  - `get_session_brief`（**现场简报**——交接核心工件，见 FR-6）
  - `query_audit` / P2：`read_screen` / `send_keys` / `wait_output`
- 全部工具声明 MCP annotations；资源：`sessions://list`

**AC**：Claude Code 与 OpenCode 均能在 5 分钟内完成接入并成功列出工具；一次 exec 全链路（Agent→授权→执行→屏幕可见→结果回传）走通；exec 端到端延迟 P95 < 300 ms（不含授权等待，SPIKE-3 验证）。

### FR-4 授权门（V1，产品核心）

- Agent 的 `exec`/`upload` 默认进入授权队列：**以任务为中心**的授权卡片——目标主机、Agent 身份与目的（intent）、逐段求值结果、会话现场状态（是否在交互程序中）、近期相关操作；人类可 **批准 / 拒绝 / 编辑后批准**
- **逐段求值**：命令先经 bash 解析器（tree-sitter-bash）解析并逐段判定；解析失败、含命令替换、管道或多段子命令时，任一段未命中允许规则即需授权。**禁止「前缀命中即整串放行」**
- 危险命令模式默认拒绝（`rm -rf /`、`mkfs`、`dd of=/dev/*`、fork 炸弹等）；**内置规则不可删除**
- 允许清单：按 (Agent 身份 × 主机 × 命令模式) 配置；保存时强制预览影响面
- **TTL 授权窗口**：限时免审（默认 2 小时）、到期自动收回、一键撤销——支撑「任务内连续授权」，避免逐条打断
- `send_keys`（P2）采用会话级授权；授权队列按任务爆发分组

**AC**：拒绝与超时在 Agent 侧表现为结构化错误（非挂起）；复合命令不能因单段命中而整串放行；「编辑后批准」实际执行编辑后的命令且记录「原文+实际执行文」；内置 deny 规则无删除入口。

### FR-5 操作记录（V1）

- 记录所有 Agent 动作与人类决定：时间、Actor（含 Agent 身份）、会话、命令/操作、输出摘要（截断）、授权结果
- **以任务/会话时间线呈现**（人类可读，与命令块索引同源）；JSONL 导出
- 人类在共享会话执行的命令随命令块进入记录（完整率 100%）
- 追加写；哈希链定位是**完整性检测**（非防本机管理员篡改，口径见 L1 §威胁模型）；规模性能优化 V2

**AC**：任何一次 Agent 执行都能在时间线中还原「哪个 Agent 发起、谁放行、执行了什么、结果如何」；记录呈现让人不需要另开终端就能回答「刚才发生了什么」。

### FR-6 交接闭环：接管契约与现场简报（V1，差异化核心）

**接管契约**——用户点击「接管」时，产品明确承诺以下分层语义，且每层状态在 UI 可见（回答「我拿回了什么」）：

1. **冻结**（默认，<1s 生效）：Agent 不得再启动新命令、传输或写入；排队中的动作全部挂起并在 UI 列出。Agent 侧收到 `ControlTakenByHuman` 明确信号。
2. **停止运行中任务**（显式选项，尽力语义）：对运行中的 exec 按 SIGINT→SIGTERM→SIGKILL 升级尝试停止，**逐条显示实际结果**（已退出含退出码 / 已升级 / 无响应）——尽力而为，不谎报成功。
3. **不承诺回滚**：已发生的修改不自动恢复；以操作记录与现场简报支持人工判断。（回滚超出 SSH 客户端能力边界，诚实标注。）

**交还契约**：人类处理完点「交还」，系统生成**更新后的现场简报**，但核心规则是——

> **交还后先更新上下文，再重新决定后续动作；旧队列不得仅因恢复控制权而自动执行。**

- **作废范围（接管生效时即触发，而非等交还）**：交接前产生、**尚未开始执行**的全部请求——**待审批、已批准待执行、排队中的传输**——一律作废并留痕；**待审批卡片作废后不可再生效**（防「相对路径命令在已变化的现场执行」类事故）；已开始运行的任务不在此列，遵循接管契约的停止条款。Agent 读取最新简报后**重新提交**（防「旧上传覆盖人工修复」类事故，见旅程 0.1）
- Agent 获知交还的路径：阻塞中的工具调用立即返回「已作废 + 最新简报」；空闲中的 Agent 由人类回到其对话窗口发送继续指令（V0 不做服务端推送，此体验限制如实告知用户）
- Agent 重新决定时基于**三层认知状态**的简报：
  1. **已确认**：cwd、运行中任务等系统可直接观察的事实；
  2. **已操作、待核实**：发生过操作但结果需要重读的对象（如「曾在 vim 中编辑 nginx.conf」）——Agent 先重读核实再操作；
  3. **无法观察**：屏幕之外、系统未追踪的状态——明确留空，不冒充已知。
- 验证版不建全量文件追踪系统；用「交还后按待核实清单重读关键对象」达到同等效果

- 现场简报是交接的核心工件，GUI（接管/交还时展示）与 MCP（Agent 主动查询）同源（双前端对等）
- 接管期间人类输入直通会话；Agent 输入被冻结层拦截

**AC**：接管 <1s 生效且 Agent 侧获得明确信号；停止选项显示真实结果（不谎报）；接管生效后**待审批、已批准待执行、排队传输**全部作废留痕、**不自动执行、旧待审批卡片不可再生效**；交还后 Agent **不要求用户重复系统已掌握的信息**，对「待核实」对象先核实再操作，缺失信息**明确提示而非忽略变化硬闯**（试点任务验证）；简报内容与操作记录一致。

### FR-7 文件传输 GUI（V2）

- SFTP 浏览器、上传下载队列与进度（Agent 侧 `upload`/`download` 工具属 FR-3，V1 已交付）

### FR-8 端口转发（V2）

- 本地/远程/动态转发配置与生命周期管理；MCP 可查询状态（创建需授权）

### FR-9 多机编排（V2 之后）

- 主机分组批量 `exec`、输出聚合、失败重试

### FR-10 终端语义化：命令块（V1 数据结构 / V2 UI）

- term-core 在屏幕网格之上维护**命令块索引**：`{命令文本, 起止时间, exit_code, 输出区间, 来源}`（L0 ADR-9）
- 块边界：OSC 133 shell 集成（本地默认；远程主机为**显式、落审计的 opt-in 动作**，可一键卸载）+ 提示符启发式兜底
- 消费方（V1）：`shell` 模式 exec 的边界与退出码、现场简报、操作记录时间线。块级 GUI 交互（点击重跑等）V2

**AC**：bash/zsh 录制集上块边界与退出码判定准确率 ≥ 98%；人类命令 100% 入块并入记录。

## 8. 关键用户旅程

### 旅程 0 · 交接闭环（核心旅程，验证版的存在理由）

1. 工程师在会话里 cd 进项目目录、激活环境，排查到一半被打断；把会话交给 Agent：「继续查这个 502」
2. Agent 查询 `get_session_brief` 拿到现场（cwd、环境、人类刚执行的命令块），**无需任何复制粘贴**，沿现场继续执行
3. Agent 每条命令走授权卡片（或命中允许清单/TTL 窗口静默执行）；屏幕上人类全程旁观（Agent 标注）
4. Agent 改了 nginx 配置并 reload，请人核对——人点「接管」（冻结 + 按需停止），vim 里改回一行，点「交还」
5. 简报自动更新：人类命令入块，且该文件被标注为「**已操作、结果待核实**」；Agent 交还后**先重读 nginx.conf 确认实际内容**再继续验证恢复——不需要人解释「我改了什么」，但系统也不假装知道文件里的每一行（简报三层认知状态，见 FR-6）

### 旅程 0.1 · 交还时的旧动作失效（交接契约的反面用例）

1. Agent 排查中已排队一条 `upload`（已批准，等待前序命令完成）
2. 人类接管，检查后发现该配置文件本身有错，亲手修好
3. 人类点「交还」——**关键规则生效：交还后先更新上下文，再重新决定后续动作；旧队列不得仅因恢复控制权而自动执行**
4. 排队中的 upload **作废并留痕**（不执行，避免覆盖人工修复）；阻塞中的工具调用立即返回「已作废 + 最新简报」
5. Agent 读简报，看到人类的修改记录与「待核实」标注，重新核实文件后**重新提交**新的上传计划——新动作基于新现场开始

### 旅程 1 · Agent 排查磁盘告警（受控执行路径）

1. 工程师对 Claude Code 说「看下 prod-1 磁盘什么占了空间」
2. Claude Code 调 `list_hosts` → `create_session(prod-1)`（远程默认需授权，主机免审除外）→ `exec("df -h && du -sh /var/* | sort -h | tail -20")`
3. 授权卡片：命令 + 主机 + Agent 身份 + 逐段求值结果；工程师点批准
4. 命令在持久会话中执行，输出实时可见；结构化结果回传 Agent
5. Agent 总结「/var/log 占 87%」，工程师决定是否继续（下一条命令再走授权）

### 旅程 2 · 断线与现场重确认（诚实的能力边界）

1. SSH 会话因网络中断掉线，操作记录与显示历史完整保留，UI 明确标注「连接已断开」
2. 网络恢复后重连成功——**旧画面重新出现，但系统明确提示「现场需重新确认」**：原 shell 的目录、环境变量已随连接消失；**运行中进程状态未知**（nohup/systemd 任务可能仍在运行）
3. 简报中 SSH 侧事实全部降级为「待核实」；Agent 的普通动作被阻止，**仅开放客户端内置的只读核实命令**（pwd/printenv/ps 等，Agent 不可自选）
4. Agent 完成核实动作，事实恢复「已确认」后自动继续（完成由核心判定，UI 全程显示重确认状态）——人类看到的是诚实的状态，而非「画面还在所以现场还在」的错觉；未知任务不会被当作已结束或自动重试

### 旅程 3 · 批量巡检（V2 之后）

1. 对 OpenCode 说「巡检 web 组所有机器的负载与证书有效期」
2. Agent 按组批量 `exec`（一次授权覆盖组内同命令），输出聚合
3. 异常机器列表回传，工程师逐台深入

**产品指标（V0 用户研究 + V1 试点）**——衡量的是「交接闭环是否成立」，不是审批行为本身：

| 指标 | 目标 | 采集 |
|---|---|---|

## 10. 里程碑

> 顺序调整（v0.3）：**先验证交接闭环，再扩大客户端广度**。技术 Spike 有必要，但当前最缺的是产品验证——两者在 V0 并行，且产品验证是 V1 的前置 gate。

| 阶段 | 内容 | 验收 gate |
|---|---|---|
| **V0 · 原型与产品验证** | SPIKE-1/2/3（macOS）；thin-slice 原型：一个真实共享会话（SSH→Linux+bash、持久 shell、授权卡片、接管/交还、现场简报、可读操作记录）；6–8 人用户研究。**首个可运行验收场景：旧请求待审批 → 人接管修改现场 → 交还 → 旧请求（含待审批卡片）失效 → Agent 核实后重新提交** | Spike 全过 **且** PV 决策 gate 通过（见 validation-plan）；PV 不过则先调交互再测，不进入 V1 |
| **V1 · 验证版** | FR-1/2 最小集（SSH config 导入）、FR-3（exec shell 默认）、FR-4、FR-5、**FR-6 交接闭环**、FR-10 块索引；试点人群日常使用 | 旅程 0 端到端；PV 产品指标达标；双 Agent 接入 |
| **V2 · 完整客户端** | FR-7/8/9、Windows/Linux（SPIKE-4 届时执行）、块级 UI、主题/搜索、审计规模优化 | 原 FR AC |

**V1 范围取舍表**（v0.3 修订核心）：

| 提前验证（V0/V1） | 暂时后移（V2） |
|---|---|
| 方便接入已有 SSH 配置 | 完整主机资产管理 |
| 一个真实的共享会话（现场延续） | 全平台、多种 shell 的完整覆盖 |
| 实时进展、明确授权、接管归还 | 多机编排、端口转发、双栏文件管理 |
| 交接后的上下文更新（现场简报） | 复杂命令块 UI、完整终端替代体验 |
| 可理解的操作记录 | 审计浏览器的规模性能优化 |

> SessionApi 接口冻结范围：仅限 V0 末冻结的 **v1 标注子集**（L1 §2）；后续能力以 ADR 增量扩展。

## 11. 竞品与差异化

> v0.3 修正：经核实（2026-09），Warp 官方文档已包含 Agent Profiles 权限体系（allow/deny 正则清单、逐动作权限、run-until-completion 自动批准）、15 个第三方 CLI Agent 支持（**含 Claude Code 与 OpenCode**）、Warpify SSH（远端安装 companion server，提供文件树/编辑器/索引/agent diff）。「别人没有审批、没有外部 Agent、只能本地」**不成立**，差异化必须重新表述。

| 产品 | 现状（核实版） | 我们的差异点 |
|---|---|---|
| Warp | 终端内 Agent 权限/审批体系；第三方 CLI Agent 以「终端里跑进程」方式接入；Warpify SSH 需在远端安装常驻 companion server | ① **远程运维纵深**：持久共享会话、接管契约、现场简报交接，为「人机交替操作同一远程现场」设计；Warp 的审批 govern 其自家 agent，第三方 CLI Agent 在远程 SSH 会话中没有客户端侧授权层。② **本地优先、零远端部署**：不在用户服务器上装任何常驻组件（Warpify 需写远端家目录、host 仅限 Linux/macOS）；凭据与主机资产本地沉淀、换 Agent 不丢。③ **开放 MCP 而非绑定终端**：任何 MCP client 接入，不要求更换终端 |
| Termius | GUI 客户端体验标杆；无 Agent 接口；闭源云同步 | 开放 MCP + 本地优先 + 交接闭环 |
| ssh-mcp-server 类 | 无头 MCP：无 GUI、无凭据托管、无授权、无现场 | 共享现场 + 知情可控 |

**竞争力最终体现在具体任务里**：连接是否省事、现场是否连续、授权是否清楚、介入是否有效——这四项由 V0 用户研究直接验证，不以「功能有无」自证。MCP 接口和授权卡片本身较容易被补上，**交接闭环的体验纵深是必须抢先验证和占据的部分**。

## 12. 风险、开放问题与理念备选池

### 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| **交接闭环不成立**（用户喜欢演示但真实任务中嫌打断、全批、不用交接） | 高（产品级） | V0 产品验证 gate 前置：先调交互与授权方式，再扩大功能投入 |
| Tauri IPC 吞吐不达标 | 高（技术级） | V0 SPIKE-1 前置验证（真实流载荷）；不达标走降级路径（L0 ADR-8） |
| 审批疲劳 / 全批 | 中 | 逐段求值 + TTL 窗口收敛免审面 + 内置 deny 不可删；授权比例作为观察指标监控两端 |
| 允许清单被写成过宽正则 | 中 | 逐段求值防复合命令绕过；影响面预览；内置 deny 兜底 |
| prompt injection 无法根除 | 高（认知） | 授权门是缓解不是消除；文档与产品文案必须明示边界（L1 §威胁模型） |
| webkitgtk（Linux）渲染能力弱 | 中（V2） | canvas/DOM 渲染器回退；Linux 平台优先级最后 |

### 开放问题（需要产品决策，不阻塞 V0）

1. 产品名（TinySSH 为工作名，「tiny」与「工作台」定位有张力）
2. 开源与否及 License
3. V0 原型是否需要 `send_keys`（专家建议的接管闭环用 exec+停止即可覆盖；vim 类交互救援可延至 V1 末期验证）

### 理念备选池（待 V1 试点数据决策）

1. **风险分级路由**：自动给命令打风险标签，只读自动放行、破坏性强制逐条并展示爆炸半径——把人类注意力花在刀刃上
2. **Agent 自报意图比对**：exec 附 `intent`，授权卡片并排展示「系统判定 vs Agent 自报」
3. **Playbook**：人类预审的参数化命令模板，Agent 调用按模板等级授权——建立在 TTL 窗口之上
4. **完整版上下文包**：块级 + cwd/env + 授权摘要 + 人类「置顶标注」的结构化交接包

## 13. 产品验证（PV）计划（摘要）

完整计划见 [validation-plan.md](validation-plan.md)。要点：

- **参与者**：6–8 人，符合 §3.1 第一批画像
- **任务**：等价的排障与配置任务，基线（现有方式）与原型对照。**引导段**安排计划内「接管→交还」（验证用户能否理解并完成）；**自由段**只给目标、不强制交接（验证用户**是否主动选择**交接及使用时机）
- **观察**：上下文重复解释动作是否减少；能否准确说出 Agent 在做什么/获准做什么；接管后是否顺畅继续；自由任务中是否自发使用交接；时间与注意力投入；一周后是否主动回用（**区分「没遇到适用任务」与「遇到但选择不用」**）
- **协作决策 gate**：**以 [validation-plan §6](validation-plan.md) 为唯一权威，PRD 不重复或另设数字**。依该计划满足进入条件后规划后续协作阶段；反模式信号（全批/打断抱怨）**优先于**偏好判据，先调整交互与授权方式再测；闭环不成立则重新评估协作假设，**暂缓新增协作投入，不阻止 UX-R1 客户端建设**。
